一、token：AI 世界的计价单位

不懂 token，就像打车不看计价器——账单来了才知道贵贱

token 是什么：模型的"字节"，账单的"度"

大模型不是按"字"或"词"处理文本的，而是按 token（词元）：模型先把文本切成一个个 token（常见词是一个 token，生僻词、长单词会被拆成几个，汉字通常一个字对应一个到两个 token），再逐个预测下一个 token（第1章讲过原理）。计费也按 token 走：你发进去的内容（提示词、上下文、材料）算输入 token，模型吐出来的内容算输出 token，两者单价不同——输出通常比输入贵数倍，因为生成比读取更耗算力。

量级感很重要，记三个粗略换算（示例口径，精确值以各厂商官方分词器为准）：①一段 500 字的中文微信消息，约 500-1000 token；②一本 20 万字的小说，约 20-40 万 token；③一次普通的"总结这篇文章"对话（文章 2000 字+输出 300 字），约 3000-5000 token。有了量级感你就能心算：API 定价页上的价格是"每百万 token 多少美元"，一次几千 token 的调用，费用是"百万分之几"的量级——这就是为什么第三节的手算示例会得出"每天一百封邮件分类只要几毛钱人民币"这种反直觉的结论。贵不贵不取决于感觉，取决于任务量×单价，两个都能算。

按量计费：AI 服务界的"水电表"

API 按量计费（pay-as-you-go）的逻辑和水电一样：装表不要钱（注册开发者账号通常免费），用多少算多少（按输入+输出 token 数×单价），账单周期结算。这个模式对个人自动化极其友好：不用就不花钱，小规模用花小钱，没有"最低消费"。对比之下，订阅制（每月固定费）像包月宽带，本地部署（买硬件自己跑）像自建发电机——三种模式没有绝对优劣，只有"用量-成本曲线"上的不同交点，第二节展开。

看定价页的三个要点。①分清模型档位：同一厂商通常有多档模型（旗舰档贵、轻量档便宜），价差可达数十倍；定价页按模型分别标价。②输入输出分开计价：估算成本时把两者分开算，输出多的任务（写长文）和输入多的任务（读长文档）成本结构完全不同。③留意特殊计价项：图像、音频通常按张/按秒另计；带缓存的输入 token 可能有折扣价；批量接口可能有折扣（第六节省钱技巧的来源）。所有具体数字随时间变动，本课程不背价格表——背下方法，用时现查官方定价页，这是应对价格快速变化的唯一可靠姿势（各厂商定价页链接见第三节）。

关于价格趋势，还有一个对决策有用的长期观察：自生成式 AI 普及以来，同等能力档位的模型单价总体呈快速下降趋势，各厂商还不断用更便宜的轻量档刷新"性价比下限"。这对你的成本决策意味着两条：①今天算不过账的任务，半年后可能算得过来——被成本否掉的候选任务别扔掉，放进清单定期重估；②不要为"以后会更便宜"而推迟值得做的自动化——回本周期以月计的任务，等降价省下的钱远小于早半年开始省下的时间。把这两条合起来就是：按现价决策、按趋势重估。

二、三本账：订阅、API、本地部署

同样一件事"让 AI 干"，三种付费模式对应三种用量曲线和三类人群

订阅制：普通人的默认入口，账最好算

订阅制就是消费级 AI 产品的月费/年费模式：固定月费，额度内随便用（通常有频率上限，如每几小时多少条消息），高级模型能力往往放在更贵的档位。它的账最简单：每月固定支出，边际成本近似为零——适合"人机对话为主、自动化为辅"的普通用户：写材料、改文案、问问题、偶尔跑个小任务。判断值不值的方法也简单：这个月你用它替代了多少次"搜索+自己整理"或"外包+等待"？省下两顿外卖钱就回本了。

订阅制做自动化的边界要清楚：①多数订阅产品的服务条款限制程序化调用（用脚本模拟网页对话可能违反 ToS，参考第4章）；②有频率上限，无人值守的批量任务容易撞墙；③额度是"对话额度"不是"API 额度"，两套体系不通用。所以订阅制的正确定位是：你坐在屏幕前用它干活；要让它在你睡觉时自动干活，请走 API。另外，不少办公套件已把 AI 能力打包进订阅（微软 365 Copilot 类，商业产品以官方页面为准），如果你已有办公套件订阅，先看套餐里含不含 AI 能力，可能不用额外花钱。

API 按量：自动化的主战场，账要会算

API（应用程序接口）是给程序调用的通道：你的脚本、工作流工具、Agent 通过 API 把任务发给模型，按 token 付费。它是无人值守自动化的标准配置——第12章会专门讲怎么接。API 账的三个变量：调用次数 × 每次的 token 量 × 单价。三个变量都能优化：次数靠任务设计（能合并的合并）、token 量靠提示词瘦身（第3章的约束写得好，token 就省得多）、单价靠模型选型（下一张卡的分级分工）。

API 模式的两条纪律。①先小额试跑再放量：新流水线先用几十条样本跑通、核对成本，再放到全量——见过太多"一晚上跑了几十万次调用"的事故，都是没试跑直接放量。②设硬性预算上限：主流厂商的开发者后台都提供用量限额与告警设置（以各官方文档为准），开户第一件事就是把月限额设上，第七节详述。API 的成本优势在于弹性：任务停了账单就停了；风险也在于弹性：出了 bug 的循环调用，账单会跟着循环。

本地部署：数据不出门的方案，账最容易被算错

本地部署=在自己电脑上跑开源模型：Meta 的 Llama 系列是最知名的开源模型家族，Ollama 把"下载并运行开源模型"简化成了几条命令，Hugging Face Transformers 是更专业的开源工具链。账面上它"免费"——没有 API 费、没有订阅费；但真实的账是：硬件（够用的内存/显卡，几千到几万元）+ 电费 + 你的调试时间 + 能力折扣。本地小模型与云端旗舰模型的能力差距是客观存在的：复杂推理、长文档、多步骤 Agent 任务，本地轻量模型的成功率会明显更低——省下的 API 费可能变成更多的人工返工。

本地部署真正无可替代的场景只有一个：数据不能出门（第4章讲过的高敏感数据场景）。此时它不是"省钱方案"而是"唯一合规方案"，账要按合规成本算。除此之外，对个人用户的经验口径是：先别买硬件——云端 API 的轻量档模型价格已经很低（下一节手算），中轻度用量下"免费额度+API 轻量档"几乎总是比自购硬件划算；等你月账单持续超过一台设备的折旧价，再考虑本地化不迟。开源模型还有许可证条款问题（部分模型对商用规模有限制），使用前读一遍模型官方的许可说明。

三本账组合：普通人的典型演进路径

三种模式不是三选一，绝大多数人的真实路径是组合演进，大致分四个阶段。阶段一：纯订阅/纯免费——刚入门，所有任务都在对话框里人机协作完成，成本≈一份订阅费或零；这个阶段的重点是练第3章的提示词功底，别急着搭流水线。阶段二：订阅+轻量 API——开始出现"想让它自己跑"的任务（定时摘要、邮件分类），注册开发者账号、吃免费额度、跑轻量档模型，月成本通常在一杯奶茶到一顿午饭之间；这个阶段最该做的是把手算四步框用起来，对每个任务建立成本直觉。阶段三：API 为主+工具订阅——流水线多了，引入工作流工具统一编排（自托管 n8n 可以把工具费压到零，商业平台按档位付费），旗舰档模型只在关键环节动用；月成本几十到几百元，但对应省下的手动时间通常已是每天一两小时量级。阶段四（少数人）：局部本地化——某类数据不能出门，或某高频任务量大到 API 账单超过硬件折旧，才引入本地部署。

这条路径的关键不是"每阶段花多少钱"，而是每次升级都由真实需求触发：任务量涨到免费额度不够了才付费，付费账单涨到工具能省更多时间了才上工具，工具化之后仍有数据合规硬需求了才本地化。反面的典型是"装备党路径"：还没跑通第一个任务，先买了显卡、订了三个平台、囤了一堆 API 额度——第2章说过的"先手动跑通再自动化"，在花钱这件事上同样成立：先用最便宜的方式验证任务值得做，再为它升级装备。判断自己该不该升级的信号只有一个：现有模式下，你是否有任务因为成本或额度限制而"想做但没做"——没有，就说明当前模式仍是性价比最优解。

三、手算示例：一个自动化任务每月花多少钱

跟着算一遍，你就获得了"看一眼任务就能估成本"的直觉——以下数字全部为教学示例

示例一：每天 100 封邮件自动分类摘要（轻量档模型）

任务：把每天收到的 100 封客户邮件自动分类（五个类别）并各生成一句摘要，结果写入表格。先估 token：每封邮件正文平均 300 字中文，约 450 token（按 1 字≈1.5 token 的示例系数）；提示词模板（第3章四件套）约 300 token；输出（类别+一句摘要）约 60 token。即每封邮件≈输入 750 token、输出 60 token。

再套单价（教学示例价，非任何厂商真实报价）：假设某轻量档模型定价为输入每百万 token 0.8 元、输出每百万 token 3 元。每封邮件费用 = 750÷1,000,000×0.8 + 60÷1,000,000×3 = 0.0006 + 0.00018 ≈ 0.0008 元。每天 100 封 ≈ 0.08 元；每月 ≈ 2.4 元——不够买一瓶水。这个反直觉的结论有普适性：轻量档模型+短文本+中等频率的"文本流水线"任务，API 成本几乎可以忽略；真正贵的是重度使用旗舰模型、超长上下文、图像音频、高频 Agent 循环这四类，见下一个示例。

手算四步框（任何 AI 自动化任务立项前算一遍，数字以官方定价页实时价替换）：
① 估单次 token：输入=材料+提示词模板，输出=期望结果，中文按 1 字≈1-2 token 粗估；
② 查单价：目标模型档位的输入价、输出价（每百万 token），分开记；
③ 单次费用=输入量÷100万×输入价 + 输出量÷100万×输出价；
④ 月费用=单次费用×日次数×30，再和第五节的"省下的人工成本"对比。
方法为本课程教学归纳；token 换算与计价口径参见 OpenAI/Anthropic 官方文档与定价页（英文），所有示例数字非真实报价。

示例二：Agent 式网页调研任务（旗舰档模型，成本翻百倍的原因）

任务：让 Agent 自动完成"调研某产品市场的五家竞品并输出对比报告"。这类任务的成本结构和邮件分类完全不同：Agent 每一步都要"看"（把网页内容或截图塞进上下文）+"想"（推理下一步动作）+"做"（输出动作指令），一个任务可能循环二三十步，每一步的上下文还越滚越长（之前的观察都要带着）。粗估（教学示例）：单次任务累计输入 30 万 token、输出 3 万 token；假设旗舰档模型示例价输入每百万 20 元、输出每百万 100 元——单次费用 = 0.3×20 + 0.03×100 = 6 + 3 = 9 元/次。每天跑 10 次就是每月约 2700 元，是邮件分类示例的一千多倍。

贵在哪，一目了然：旗舰单价（×25）、超长上下文（×400 倍 token 量）、多步循环（×30 步）。三个乘数都来自任务设计而非"AI 本身贵"——所以省钱的全部艺术就是砍这三个乘数：能用轻量档就不用旗舰档、能压缩上下文就不带全文、能十步走完就不循环三十步（第六节展开）。立项时的正确姿势：先用手算框估一版，再用几十条真实样本试跑，用开发者后台的实际用量数字校准估算——估算和实测差十倍是常事，差在哪一步，账单会告诉你。

顺带把多模态的成本直觉也建立了：图像和音频是另一套计价体系，量级普遍高于纯文本。图片输入通常按张或按分辨率折算 token 计费，一张高清截图折算的 token 可能顶几千字文本；语音转写按音频时长计费（如 Whisper 类服务的官方 API 按分钟计价，开源版本地跑则只花电费，第10章详讲）。所以"让 Agent 每一步都看截图"的电脑操作类自动化（第7章），成本天然高于"读文本干活"的流水线——设计时用能拿到结构化数据的地方就别截图（读网页 HTML 比看网页截图便宜且准确），这是多模态场景的第一省钱原则。视频理解类任务再把图片逻辑乘以帧数，成本敏感度更高，立项前务必先用几秒钟素材试算。

四、隐性成本：账单之外的四座冰山

API 费只是水面上的十分之一：搭建、维护、失效、出错，才是个人自动化的真实成本结构

时间成本：搭建与调试是最大的一笔

对个人用户，自动化的成本大头是你的时间。一个"每周五自动把 30 个表格拼成周报"的流水线，从零到稳定通常要经历：理解工具（1-2 小时）→搭出第一版（1-2 小时）→调试边界情况（数据缺列、格式变化、编码问题，2-4 小时）→接入 AI 环节并调提示词（1-2 小时）→试运行一周修修补补（累计 1-2 小时）。合计 6-12 小时——这是"搭建成本"。它的残酷之处在于：无论任务以后跑多少次，这笔投入都已经发生；任务跑得越少，摊到每次的时间成本越高。这就是第五节"自动化悖论"的算术基础。

调试时间还有一个反直觉的规律：自动化把"低强度重复劳动"换成了"高强度认知劳动"。手动拼表格 30 分钟是体力活，可以边听播客边干；调试流水线为什么报错 2 小时是脑力活，全神贯注还不能保证修好。所以"自动化一定轻松"是错觉——它轻松的是稳定运行之后的每一次执行，前提是你能熬过搭建调试期，并且任务足够高频，让稳定运行的次数把搭建成本摊薄。

维护、失效与错误：三座持续滴水的冰山

维护与失效成本：自动化依赖的外部世界会变。网页改版，你定位按钮的选择器就失效（第6章会讲选择器为什么脆弱）；平台调整接口或风控，昨天还通的流程今天就断；模型升级换代，原来调好的提示词输出风格漂移（第3章的验收要重跑）。经验口径：依赖网页界面的自动化，失效是常态不是意外——不是"会不会坏"而是"多久坏一次"；每次修复 0.5-2 小时。降低失效成本的设计在第8章、第15章讲：优先官方 API（比模拟点击稳定一个量级）、失败告警（坏了立刻知道，而不是错了三个月才发现）、模块化（坏哪段修哪段）。错误成本：自动化出错时的代价不对称——AI 把重要邮件分错类你可能毫无察觉（静默错误），把汇总数字算错直接进了报表（下游污染），批量操作把不该删的删了（不可逆损失）。所以第4章的人工兜底、第3章的验收测试、第15章的抽查机制，本质上都是在为"错误成本"买保险：保险费是每次多花十秒确认，赔付上限是避免一次事故。

五、ROI 粗算与"自动化悖论"

省下的钱大于花掉的钱才值得做——包括花掉的时间

ROI 粗算公式：把时间统一折算成钱

投资回报率（ROI）的自动化粗算版，一行公式：月收益 = 每月省下的小时数 × 你的时薪；月成本 = 订阅/API/服务器费用 + 每月维护小时数 × 你的时薪；月收益 > 月成本，才值得维持。时薪怎么定？上班族可以用"月薪÷实际月工时"做起点，但更推荐用机会成本口径：这一小时如果不干这个，你能创造/享受的价值是多少——对自由职业者是接单时薪，对上班族可能是"准时下班陪家人"的主观价值。这个公式最容易被低估的项是"每月维护小时数"：很多人只算搭建的一次性投入，忘了网页改版、提示词漂移带来的持续小修（第四节）。

算一个完整例子（示例）：自动整理发票任务，手动每月 4 小时；搭建自动化花了 8 小时，之后每月维护约 0.5 小时；API 费每月约 5 元；你的时薪按 100 元计。月收益 = 4×100 = 400 元；月成本 = 5 + 0.5×100 = 55 元；净赚 345 元/月，搭建投入 8 小时（800 元）约 2.3 个月回本——值得做。再把参数改一下：如果这任务每月只手动花 30 分钟，月收益 = 50 元，扣除维护后净亏，且永远回不了本——不值得做，老老实实手动。同一项技术，频率差八倍，结论完全反转：这就是为什么"什么任务值得自动化"（第2章）必须先于"怎么自动化"。

用这个公式给任务排队，就得到了你的自动化优先级清单：把候选任务逐个算出"回本月数"（搭建投入÷月净收益），按回本速度排序，先做回本最快的。两个修正项别忘加：①确定性权重——手动做经常出错、错了代价高的任务（对外数据、财务数字），即使回本慢也值得提前做，因为买的是"每次都一样对"；②复用系数——如果某任务的组件（登录模块、通知模块、数据清洗步骤）能被后面三个任务复用，它的真实搭建成本要按分摊算，优先级应上调。排完序你会发现一个普遍规律：高频、规则清晰、错误可挽回的任务排在最前面——这和第2章的选型四问、第19章的翻车复盘结论完全一致，殊途同归。

自动化悖论：为了省 10 分钟，花了 3 小时

"自动化悖论"（工程师圈的老话题，xkcd 那幅著名漫画也算过这笔账）：你花 3 小时搭建自动化，去替代一个每周 10 分钟的手动任务——回本需要 18 周；如果任务每月才一次，回本要一年半；如果期间网页改版任务失效，可能永远回不了本。悖论的扎心之处在于：越懂技术的人越容易掉进去，因为"搭自动化"本身有趣，而"手动做任务"枯燥——于是我们用"提高效率"的名义，做了一件降低效率的事。识别信号很简单：当你搭自动化的动机里有"好玩""炫技""不想碰那个烦人的手动活"时，先拿出 ROI 公式冷静算一遍。

但悖论有另一面，三个正当理由可以让"算不过账"的自动化依然值得做：①学习价值——本课程语境下，用一个小任务练手工作流工具，学到的是能复用到未来所有任务的能力，这笔账不能只按单任务算；②错误率价值——手动做容易错且错了难查的任务（数据搬运、格式转换），自动化的收益不止省时间，还有"每次都一样对"的确定性；③复利价值——第一个自动化最贵（工具、账号、模式都要从头摸索），第二个开始复用已有组件，边际搭建成本递减；今天"算不过账"的小流水线，可能是明天大流水线的预制件。结论：悖论防的是"为自动化而自动化"，不是防学习投资——分清你这一单是哪种。

六、省钱六招：把三个乘数砍下来

单价×token 量×次数，每一项都有成熟的砍法——省钱靠设计，不靠抠门

前三招：模型分级、缓存复用、批量折扣

招式一：小模型干粗活，大模型干精活（模型分级/路由）。流水线的多数环节是"粗活"：分类、抽取、格式转换——轻量档模型足够；只有少数环节需要旗舰档的推理力。把流水线拆开，每个环节单独选档，常见能省 50%-90% 的 API 费（具体比例取决于任务构成，示例口径）。判断方法：先用轻量档跑测试集（第3章），正确率达标就用它，不达标再升档——默认从最便宜的档试起。招式二：缓存复用。重复的输入不重复付费：①提示词模板部分固定不变，多数厂商提供提示缓存类机制，命中缓存的输入 token 有折扣价（各家机制与折扣以官方文档为准）；②同样的问题问过就别再问——给流水线加一层"结果缓存"（输入指纹→输出结果的对照表，命中直接返回）；③RAG（检索增强，第14章详讲）本质也是省 token：与其每次把整本手册塞进上下文，不如只检索相关段落。招式三：批量与非实时接口。对时效不敏感的任务（夜间跑的报表、周报汇总），用厂商的批量接口通常有折扣（以官方定价页为准）；工作流工具里把"来一条调一次"改成"攒一批调一次"，还能摊薄每次请求的固定开销。

后三招：免费额度、开源方案、任务瘦身

招式四：吃透免费额度。多数厂商给新账号免费试用额度；开发者平台常有长期免费层（每月一定量的免费调用）；开源模型通过 Ollama 本地跑是零 API 费。学习阶段（比如跟本课程做练习）的正确姿势：免费额度+本地小模型打底，只在验收关键效果时动用付费旗舰档——学费可以基本控制在零。招式五：开源与自托管工具。工具层同样有订阅账：商业工作流平台按任务量/席位收费，而 n8n 可自托管（其官方口径为 fair-code 许可，非纯开源，商用前读许可条款）、Playwright/Selenium 完全免费开源。工具订阅费在重度用量下可能超过 API 费，选型时把两本账一起算（第2章的选型四问里"预算"一问的展开）。招式六：任务瘦身。最便宜的 token 是不需要处理的 token：输入侧——材料先粗筛再进模型（用规则过滤掉明显无关的邮件，比让模型每封都读便宜两个数量级）、上下文只带必要段落、长对话定期摘要压缩；输出侧——第3章的格式约束写得越死，模型输出的废话越少（"只输出 JSON，不输出解释"直接砍掉一半输出 token 的案例很常见）；频率侧——每小时轮询改成每天一次，成本直接除以 24。六招的共同哲学：先优化任务设计，再优化模型选型，最后才是砍单价——顺序反了就是事倍功半。

七、预算与监控：别让账单给你惊喜

无人值守系统必须有钱包闸口：上限、告警、复盘，三件套一次配齐

三道闸口：硬上限、用量告警、周期复盘

API 计费的弹性是双刃剑：bug 导致的死循环调用，能在几小时内烧掉平时几个月的预算——"账单爆炸"是自动化社区最常见的事故类型之一。三道闸口一次配齐：①硬上限——在厂商开发者后台设置月度消费上限（多数厂商支持，以各官方文档为准），到顶自动停服务；宁可流水线停摆，不可账单失控——停摆是已知损失，失控是未知损失。②用量告警——设置阈值告警（如日用量超过平常三倍时发邮件/短信通知你），异常在第一天就被发现，而不是月底看账单才知道。③周期复盘——每月花十分钟看一次用量明细：哪个任务花的钱最多？有没有已经不需要还在跑僵尸流水线（搭完就忘的定时任务是最常见的钱包漏洞）？单价有没有降（AI 服务价格长期趋势是下降的，你的模型选型可以定期重估）？

给流水线本身也装上"省钱保险丝"：重试次数设上限（第3章失败协议的工程侧——失败重试是善意的，无限重试是烧钱的）；单次调用的输入输出 token 数设上限（防超长内容意外进入上下文）；循环类 Agent 设最大步数（第13章会讲步数上限是 Agent 安全的标配）。这三条配置花不了十分钟，却能把最坏情况的损失从"未知"变成"有界"。成本控制的本质不是抠单价，是给不确定性设边界——这句话同样适用于下一章开始的浏览器自动化：那里要设的边界是频率与超时。

最后补一个读账单的实用习惯：主流厂商的开发者后台都能按 API 密钥分别统计用量，而密钥是可以多发几把的。给每条流水线（或每类任务）单独建一把密钥，账单里就能直接看到"邮件分类花了多少、周报汇总花了多少、上周的实验跑了多少"——不用自己记账，成本自动按任务归集。发现某条流水线成本异常时，先查三件事：调用次数是不是涨了（触发器配置错误导致重复执行？）、单次 token 是不是涨了（上游把整页内容塞进了上下文？）、模型档位是不是被谁改了（调试时升到旗舰档忘了改回来？）。这三问覆盖了账单异常的大多数原因，也是第15章编排监控的雏形：让每一笔钱都能对应到一个任务，让每一个异常都能在一天内被看见。

八、谣言粉碎与本章自测

关于成本的四个流行错觉，每一个都会让你的决策跑偏

谣言粉碎：成本认知四大错觉

错觉一："AI 自动化很贵，是企业的专利。"——错。第三节手算过了：轻量档模型的文本流水线，每月成本常在一杯奶茶钱以内；加上各家免费额度与开源本地方案，个人学习阶段的成本可以压到接近零。真正贵的四种用法（旗舰档、长上下文、图像音频、高频 Agent 循环）恰恰都是可以被设计规避的。错觉二："免费的够用了，不用算账。"——半错。免费额度适合学习与轻用，但它通常有速率限制与档位限制，把它当生产依赖，任务会在最忙的时候撞墙；而且"免费"不等于零成本——你的时间与数据仍然是投入（第4章：向免费服务投喂敏感数据的隐性代价可能远超订阅费）。错觉三："本地部署一定比 API 省钱。"——错。本地部署的账=硬件+电费+调试时间+能力折扣，中轻度用量下几乎总是输给"免费额度+轻量档 API"（第二节）；它的不可替代价值在"数据不出门"，不在省钱。错觉四："ROI 算得过账就一定该自动化。"——片面。公式之外还有三件事：任务频率会不会变（明年还做这事吗）、错误代价承不承受得起（算得过账但一次事故就清零的任务，要么加人工兜底要么不做）、你有没有维护它的意愿（三个月后失效了谁来修）——第2章"什么时候不该自动化"的账，要和 ROI 一起算。

📌 本章要点速览：token=模型处理与计费的最小单位，中文 1 字≈1-2 token（粗估），输入输出分开计价、输出更贵；三本账=订阅制（人机对话，边际成本≈0，但限程序调用）、API 按量（无人值守自动化的主战场，先试跑再放量+设硬上限）、本地部署（为"数据不出门"而非省钱，账=硬件+电费+时间+能力折扣），普通人按"订阅→轻量API→API+工具→局部本地化"由真实需求触发逐级演进；手算四步框=估 token→查单价→单次费用→月费用（本章全部数字为教学示例，真实价以官方定价页为准，截至 2026 年 10 月）；文本流水线常便宜到忽略（示例月成本 2.4 元），Agent 循环贵千倍（旗舰单价×长上下文×多步循环三个乘数）；隐性成本四冰山=搭建调试（最大头）、持续维护、网页改版失效（常态非意外）、错误代价（静默错误最险）；ROI=省下小时×时薪 vs 费用+维护小时×时薪，频率差八倍结论反转；自动化悖论="为省 10 分钟花 3 小时"，学习价值/错误率价值/复利价值三个例外；省钱六招=模型分级、缓存、批量、免费额度、开源自托管、任务瘦身（最便宜的 token 是不处理的 token）；三道闸口=消费硬上限、用量告警、周期复盘（清僵尸流水线），流水线加三条保险丝=重试上限、token 上限、Agent 步数上限。至此第一部分完结——下一章进入实操：让机器人替你点网页。
