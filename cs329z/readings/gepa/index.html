GEPA: Reflective Prompt Evolution Can Outperform Reinforcement Learning

一句话总结：GEPA（Genetic-Pareto）用「反思式提示进化」优化复合 AI 系统：让 LLM 直接阅读系统的执行轨迹（推理、工具调用、报错信息），用自然语言反思提出更好的提示，并以 Pareto 式候选选择保持探索多样性。结果在四个基准上平均超过强化学习方法 GRPO 10%、最高 20%，rollout 用量却少至 1/35——语言反馈是比标量奖励信息密度高得多的学习信号。

背景与要解决的问题

把 LLM 系统适配到新任务，主流做法之一是 RL（如 GRPO）：把任务成败压成一个标量奖励，再估计策略梯度更新权重。本文指出这条路线的三大痛点：

  • 样本效率极低：RL 方法「通常需要数万次 rollout 才能适配新任务」——论文中 GRPO 基线用了 24,000 次 rollout；
  • 信号浪费：系统运行本来就产生大量自然语言轨迹——指令、推理链、工具调用与输出、编译器报错、检索失败、约束违反报告——标量奖励把这些诊断信息全部丢弃；
  • 现实约束：工具调用昂贵、推理预算有限、最强的闭源模型根本不允许更新权重。

核心问题：如何从每次昂贵的 rollout 中榨取更多学习信号？

核心观点

观点 1：语言反馈 > 标量奖励

"GEPA samples system-level trajectories (e.g., reasoning, tool calls, and tool outputs) and reflects on them to propose improved prompts." GEPA 采样系统级执行轨迹（推理、工具调用、工具输出等）并对其进行反思，从而提出改进后的提示。

GEPA 把评价函数从「数值指标 μ」扩展为「反馈函数 μ_f」：除分数外还返回文本反馈（错误消息、评估器评语等），供反思用的 LLM 直接阅读、诊断失败原因并改写提示。

观点 2：遗传进化 + 反思变异，形成提示「族谱」

GEPA 维护一个候选系统池（每个候选 = 各模块的一组提示），循环执行：选一个有前途的候选 → 选一个要改进的模块 → 在小批量训练样本上运行、收集轨迹与反馈 → 让 LLM 反思并提出该模块的新提示 → 测试变异后的系统 → 小批量成绩提升则保留。由此形成一棵祖先树，后来的候选继承早先的经验教训。

观点 3：Pareto 式候选选择是成败关键

"GEPA stochastically explores the top-performing prompts for each problem instance." GEPA 随机地探索在每个问题实例上表现最好的那些提示。

不是永远变异「全局平均分最高」的候选，而是追踪每个训练实例上谁最好，构建实例级 Pareto 集、剔除被支配的候选，再从中采样。这样能保留多样化的「获胜策略」、避免过早收敛到局部最优。消融实验证明其重要性：换成贪心选最优（SelectBestCandidate）后，Qwen3-8B 聚合分从 61.28 掉到 54.89（-6.4，单项最大差距 8.17%）。

观点 4：系统感知合并（system-aware merge）

若两个候选谱系源自共同祖先、且各自改进了不同模块的提示，GEPA 可以做「交叉」：把两个谱系中更好的模块提示合并成一个新候选。在 GPT-4.1 mini 上合并带来最高约 5% 的单项提升、聚合约 +1.7 分。

方法与架构

组件作用
候选池 + 祖先树保存历史提示谱系，支持继承与回溯
反思式变异（reflective mutation）LLM 阅读轨迹/反馈，诊断失败并提出新提示
反馈函数 μ_f在数值指标之外返回文本反馈（报错、评语）
Pareto 候选选择按实例级最优构建 Pareto 集并采样，防局部最优

推理时搜索用法把测试任务集同时当训练集与 Pareto 集，可在推理期过拟合固定任务（如代码 kernel 优化）
与 MIPROv2（本讲扩展阅读）的区别：MIPROv2 用贝叶斯代理模型在「指令 + few-shot 示例」组合空间搜索，信号来自分数；GEPA 只进化指令（暂不优化 few-shot 示例），但用自然语言反思代替分数驱动的提议，单次 rollout 的信息利用率高得多，产出的提示也更短（可达 MIPROv2 提示的 1/9.2 长度）。

推理时搜索：代码 kernel 优化

  • NPUEval（GPT-4o）：Sequential10 基线平均向量利用率 4.25%，+RAG 16.33%，+MIPROv2 19.03%；GEPA 达 30.52%（部分 kernel 高达 70%），单一 GEPA 提示无需运行时 RAG 也有 26.85%；
  • KernelBench（CUDA）：随搜索预算增加，GEPA 把接近 0% 的 fast_1 分数提到 20% 以上（35 个代表性任务）。

结论与局限

  • 自然语言反思可以是比稀疏标量奖励更强的学习信号；Pareto 选择对避免局部最优至关重要；
  • 局限：数据充足时权重更新（RL/微调）仍可能胜出；GEPA 暂不优化 few-shot 示例；相当一部分 rollout 花在验证而非学习上；Merge 的预算与时机尚需研究（Qwen3-8B 的 IFBench 上 Merge 反而大幅掉分）。

影响与课程关联

  • 课程定位：CS329Z 第九讲（Optimization）把提示优化方法并列为 GEPA、MIPROv2、OPRO、TextGrad——本文是其中「反思式进化」路线的代表与课程必读，并与 RLHF/GRPO 路线正面对比，直接回答「优化提示还是优化权重」。
  • 作者关联：作者阵容与课程高度重合——Michael J Ryan（CS329Z 讲师）、Omar Khattab（ColBERT/DSPy，第三讲扩展阅读 ColBERT 一作）、Matei Zaharia（第一讲必读 Compound AI Systems 一作）、Krista Opsahl-Ong（本讲扩展阅读 MIPROv2 一作）。
  • 工程启示：对昂贵工具调用、闭源模型（无法微调）或小训练集场景，GEPA 式反思优化是当前样本效率最高的适配手段之一；已集成于 DSPy（dspy.GEPA）。
