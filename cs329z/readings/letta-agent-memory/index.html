Agent Memory: How to Build Agents that Learn and Remember

智能体记忆：如何构建会学习、会记忆的智能体

TL;DR 背景与问题 核心观点 记忆架构剖析 结论与建议 影响与课程关联 术语对照
一句话总结：这是 MemGPT 团队（Letta）对「智能体记忆」的工程化总结：智能体记忆的本质是上下文管理——智能体记住什么，取决于哪些内容进入上下文窗口、如何组织、以及如何从外部存储召回。文章给出一套可直接落地的分层记忆架构（消息缓冲区 → 核心记忆块 → 回忆存储 → 归档存储），并提出「记忆块（memory blocks）」这一把上下文窗口模块化、可被智能体自动管理的关键抽象。

背景与要解决的问题

传统 LLM 应用的每次交互都是孤立的：模型不会从上一次对话中「学到」任何东西，这使其难以成为长期陪伴用户、持续适应的智能体。要让智能体跨会话地学习与记忆，就必须系统性地设计「记忆」——这正是 Letta（由 MemGPT 论文作者创立）在这篇博客中要回答的问题：智能体记忆是什么？由哪些部件组成？工程上如何构建？

"Agent memory is what and how your agent remembers information over time." 智能体记忆，指的是你的智能体随时间推移记住什么信息、以及如何记住这些信息。

核心观点

观点 1：记忆 = 上下文工程，而非某种单一技巧

文章的基本立场：LLM 只能「看到」上下文窗口中的 token，所以智能体记忆问题可以还原为三个子问题——哪些内容进入上下文窗口？如何组织？如何从外部存储中召回？记忆的构建没有银弹，而是多种机制的组合：旧消息清退与摘要、记忆块的读写、外部存储的检索。

观点 2：分层记忆——从「短期」到「长期」的四个层次

"The message buffer stores the most recent messages in a conversation." 消息缓冲区保存一次对话中最近的消息。

Letta 把智能体记忆划分为四层（详见下节表格）：消息缓冲区（message buffer）、核心记忆（core memory）、回忆存储（recall memory）、归档存储（archival memory）。这一划分直接继承 MemGPT 的「上下文窗口 ≈ RAM、外部存储 ≈ 磁盘」操作系统式思路。

观点 3：记忆块（memory blocks）是核心抽象

"Memory blocks abstract the context window for automated management." 记忆块对上下文窗口做了抽象，使其可被自动管理。

记忆块是结构化的上下文单元，包含标签（label）、描述、实际内容与长度上限，围绕用户、组织、任务等主题保存信息。其关键性质：

  • 常驻上下文：核心记忆块始终在上下文窗口内，无需检索即可用；
  • 可编辑：智能体自己可以改写自己的记忆块（沉淀用户偏好、任务目标等长期信息）；
  • 可共享/跨智能体：其他智能体也可以更新同一个记忆块（对应第七讲「跨智能体记忆」主题）；
  • 可托管维护：专门的异步记忆智能体可以在空闲时整理、压缩、优化记忆块，不阻塞实时响应。

观点 4：归档记忆是显式外化的知识

"Archival memory represents explicitly formulated knowledge stored in external databases." 归档记忆代表存放在外部数据库中的、被显式表述的知识。

归档记忆经过处理和索引，可用向量数据库（语义检索）或图数据库（关系查询）存储，通过工具调用取回上下文——与 RAG 的关系密切，但由智能体自主决定读写。

观点 5：不必机械模仿人类记忆

文章特别提醒：智能体记忆的目标不是复刻人类认知科学中的记忆分类，而是在 token 限制下做有效的上下文工程——工程有效性优先于拟人性。

记忆架构剖析

层次位置内容管理方式
Message buffer（消息缓冲区）上下文窗口内最近的对话消息，维持当前会话流短期内容，超出容量时被清退（部分清退 + 摘要，摘要可递归合并）
Core memory（核心记忆）上下文窗口内（常驻）围绕用户/组织/任务主题的可编辑记忆块智能体自己或其他智能体通过工具更新
Recall memory（回忆存储）外部存储完整交互历史可搜索、可调取；Letta 自动保存
Archival memory（归档存储）外部存储显式表述的知识（处理后索引）向量库/图库存储，通过工具检索回上下文

智能体「学习」的四条途径

  1. 清退 + 摘要：旧消息被部分清退并生成摘要，摘要可递归合并——保留连续性而非全删（文中示例：可清退约七成旧消息）；
  2. 核心记忆更新：把用户偏好、任务目标等长期信息沉淀进常驻记忆块；
  3. 外部检索：归档/回忆存储中的知识按需重新进入上下文；
  4. 异步记忆智能体：空闲时在后台重构记忆，既提升记忆质量又不阻塞实时响应。

结论与建议

本文为工程博客，无实验数据，其结论是一组架构建议：

  • 采用分层记忆：近期消息、核心记忆、可查历史、外部档案各司其职；
  • 清退旧消息时不要全删，保留摘要以维持连续性；
  • 记忆块应有边界、可编辑，并可由智能体或专门的记忆智能体维护；
  • 外部存储按数据形态选向量检索（语义相似）或图查询（关系推理）；
  • 沿用 MemGPT 的 OS 式思路：上下文窗口像高速内存，外部存储像磁盘；
  • 用异步记忆管理提升响应速度与记忆质量；
  • 提示词应帮助智能体理解自身的记忆限制；
  • 不必机械模仿人类记忆，重点是 token 限制下的有效上下文工程。
"Agent memory represents one of the most critical frontiers in AI development." 智能体记忆是 AI 发展中最关键的前沿之一。
