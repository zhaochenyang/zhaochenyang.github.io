A Dynamic LLM-Powered Agent Network for Task-Oriented Agent Collaboration

面向任务的动态 LLM 智能体协作网络（DyLAN）
Zijun Liu, Yanzhe Zhang, Peng Li, Yang Liu, Diyi Yang（Tsinghua / Georgia Tech / Carnegie Mellon）· COLM 2024（arXiv 2023）
阅读原文（arXiv） 专栏首页
TL;DR 背景 核心观点 方法与架构 实验结论 影响 术语
一句话总结：DyLAN 针对既有多智能体方法「智能体数量固定、通信结构静态」的局限，提出按任务动态组队：先在预备阶段用无监督的智能体重要性得分（Agent Importance Score）从候选池中筛选出最优团队，再在求解阶段按查询动态调整通信图、支持提前收敛停止——在代码生成、决策、通用推理与算术推理四类任务上以适中计算开销取得一致提升（MMLU 特定学科组队最高提升 25.0%）。

背景与要解决的问题

既有多智能体协作方法有两个通病：团队构成固定（不论什么任务都用同一批角色）与通信结构静态（消息传递拓扑事先写死）。然而不同任务需要不同专长：数学题需要推理强的智能体，代码题需要会写测试的智能体；同一任务内部，不同查询的难度与类型也不同。

DyLAN 要回答：能否自动地从候选智能体池中为每个任务挑选团队，并在求解过程中动态调整协作结构？

核心观点

观点 1：协作结构应随任务而变

论文把多智能体协作建模为时间分层的前馈图（time-layered feed-forward graph）：每一层是一个交互步，节点是该步的智能体，边是消息传递。这个形式化让「动态通信结构」成为可计算的对象，而非工程 trick。

观点 2：智能体重要性可以被无监督地度量

不需要人工标注谁重要：让后层智能体给前层智能体的回答打分，再把分数沿图反向传播聚合，即可估计每个候选智能体的贡献——「智能体重要性得分」由此而来。

观点 3：少而精胜过多而杂

"Fewer proper agents in a team could have better performance." 团队中更少但更合适的智能体，反而可能带来更好的表现。

实验反复验证了这一点：缩减候选团队常常提升准确率并大幅节省 API 调用（见下文）。

方法与架构

"DyLAN adopts a two-stage paradigm." DyLAN 采用两阶段范式。

阶段一：团队优化（Team Optimization）

  1. 预备协作：候选智能体先在试跑任务上协作一轮，形成分层交互图；
  2. 评分（Rating）：后层智能体对其收到的前层智能体回答打分；
  3. 反向聚合：前层智能体的重要性 = 后层智能体重要性 × 所得评分，沿图反向传播更新；最终层得分先初始化并归一化，回答顺序随机打乱以消除位置偏差；
  4. 选择：跨层累加每个智能体的得分，取 top-k 组成任务专属团队。

阶段二：任务求解（Task Solving）

  • 入选智能体对真实查询协作求解；LLM 排序器在运行中评估各智能体的当前回答，只让较强者进入后续层——通信图随查询动态改变；
  • 提前停止：当超过三分之二的智能体收敛到一致答案时，可提前结束迭代，节省计算。

关键观察：

  • 按学科组队收益巨大：MMLU 特定学科上用该学科最优团队，准确率最高提升 25.0 个百分点（如大学数学从 40.0 → 65.0）。
  • 团队瘦身：候选池经优化普遍缩小（代码生成 12→8、决策 8→4、通用推理 7→4）；一个 3 智能体的通用推理团队即可超过筛选前配置与 4 智能体辩论（debate）基线，同时 API 用量分别减少 52.9% 与 67.8%。
  • 提前停止：算术推理省 45.0%、通用推理省 66.2%、代码生成省 11.3%、决策省 54.2% 的 API 调用，且准确率略有上升。
"DyLAN improves overall performance on different tasks with a reasonable computational cost." DyLAN 以合理的计算开销，在不同任务上全面提升了整体性能。

影响与课程关联

  • 领域地位：DyLAN 是「动态组队」路线的早期代表（2023 年 10 月），把多智能体协作形式化为分层图并给出无监督的智能体贡献度量，发表于 COLM 2024；其一作来自 Diyi Yang（CS329Z 主讲教授）的 Georgia Tech 实验室，与本课程内容同源。
  • 与课程的关联：CS329Z 第 8 讲讨论编排模式与「谁该参与协作」。DyLAN 给出的答案是：参与者不应事先固定，而应按任务重要性得分动态选择；这与 AutoGen 的「对话即编排」互补——AutoGen 定义了对话机制，DyLAN 优化对话的参与者与拓扑。其「提前收敛停止」也是本讲「停止准则」设计的一个具体实例（与第 12 讲评测 4 元组呼应）。
  • 实践启示：多智能体系统上线前值得做一轮「团队消融」：跑重要性评分、砍掉低贡献成员，往往既省钱又提效——这与《Don't Sleep on Single-agent Systems》的告诫殊途同归：结构要服务于任务，而非相反。
