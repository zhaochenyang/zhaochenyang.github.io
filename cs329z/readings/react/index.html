一句话总结：ReAct 让冻结的大模型交替生成推理轨迹（reasoning traces）与任务动作（actions），形成「思考 → 行动 → 观察」（thought–action–observation）循环：推理负责制定、跟踪、更新行动计划并处理异常，行动负责从外部环境获取新信息。在 HotpotQA/FEVER 上通过与简单 Wikipedia API 交互显著缓解思维链的幻觉与错误传播；在 ALFWorld/WebShop 决策任务上仅用 1–2 个上下文示例就以绝对成功率 +34% / +10% 超过模仿学习与强化学习方法。ReAct 是「推理 + 工具调用」智能体范式的定名之作。

背景与要解决的问题

论文开篇指出：尽管 LLM 在语言理解与交互式决策上表现出色，但其推理能力（如思维链提示 chain-of-thought prompting）与行动能力（如行动计划生成）此前主要被当作两个独立课题来研究：

"...their abilities for reasoning (e.g. chain-of-thought prompting) and acting (e.g. action plan generation) have primarily been studied as separate topics." ……它们的推理能力（例如思维链提示）与行动能力（例如行动计划生成）此前主要被作为独立课题来研究。

两条路线各有致命短板：

  • 只推理不行动（CoT-only）：仅依赖模型内部知识闭门推理，容易产生幻觉（hallucination）与错误传播（error propagation）——一步编造事实，后续全盘皆错，且无法从外部获取纠正信息；
  • 只行动不推理（Act-only）：直接生成动作、缺少显式推理，难以做高层目标分解与规划、难以跟踪环境状态、出错后无法恢复。

作者从人类认知获得启发：人类智能的独特之处在于能无缝地把任务导向的行动与言语推理（inner speech）结合起来。ReAct 就是把这种结合搬进 LLM 提示范式。

核心观点

观点 1：推理与行动交替生成、互相增强

"...reasoning traces help the model induce, track, and update action plans as well as handle exceptions, while actions allow it to interface with and gather additional information from external sources such as knowledge bases or environments." 推理轨迹帮助模型归纳、跟踪并更新行动计划、处理异常；而行动让模型能够与知识库或环境等外部来源交互并获取额外信息。

即所谓 reason to act（推理以行动）与 act to reason（行动以推理）的协同：模型每一步先输出一段自然语言思考（分析现状、分解子目标、决定下一步动作），再输出一个具体动作；环境返回观察结果（observation）后进入下一轮循环。

观点 2：与外部信息交互可治思维链的「幻觉病」

"ReAct overcomes prevalent issues of hallucination and error propagation in chain-of-thought reasoning by interacting with a simple Wikipedia API, and generating human-like task-solving trajectories that are more interpretable than baselines without reasoning traces." ReAct 通过与一个简单的 Wikipedia API 交互，克服了思维链推理中普遍存在的幻觉与错误传播问题，并生成比无推理轨迹的基线更可解释的、类人的解题轨迹。

论文的人工错误分析印证了这一点：HotpotQA 上 CoT 失败案例中 56% 源于幻觉，而 ReAct 失败案例中幻觉占 0%（详见下文）；ReAct 成功轨迹中「事实与推理均正确」的比例达 94%（CoT 为 86%）。

观点 3：少示例即可超越微调/RL 专用方法，且支持人在环修正

"...ReAct outperforms imitation and reinforcement learning methods by an absolute success rate of 34% and 10% respectively, while being prompted with only one or two in-context examples." ReAct 以绝对成功率 34% 与 10% 的优势超过模仿学习与强化学习方法，而它仅使用一到两个上下文示例进行提示。

在 ALFWorld/WebShop 这类需要 thousands of 训练样本的决策基准上，ReAct 只用 1–2 个手写示例轨迹即可取胜。更重要的是可解释性带来的可控性：由于思考过程是自然语言，人类可以直接编辑模型的推理句来纠正行为（论文附录 A.3 的 human-in-the-loop 示例，见图 3），这是黑盒 RL 策略做不到的。

观点 4：内部知识与外部信息应当组合使用

ReAct 并非在所有设置下都单独最优——纯 ReAct 在 HotpotQA 上的 EM（27.4）低于 CoT-SC（33.4）。论文提出两种组合策略：CoT-SC → ReAct（先用自洽采样思维链作答，模型对答案不确定时才转入 ReAct 检索验证）与 ReAct → CoT-SC（ReAct 检索反复失败时回退到 CoT-SC 用内部知识作答）。组合后的方法在两个数据集上均取得全场最佳（34.2 / 64.6 与 35.1 / 62.0），说明内部推理与外部行动是互补资源，最优系统应当动态地在两者之间切换。

方法与实验设置

ReAct 是纯提示方法：冻结 LM（主实验用 PaLM-540B），在上下文里放 1–6 条人工编写的「思考+行动」示例轨迹，模型即可在新任务上延续该格式。实验覆盖两大类四个基准：

类别基准动作空间示例数
知识密集型推理HotpotQA（多跳问答）简单 Wikipedia API：search[entity]（搜索实体）、lookup[string]（在页面中查找下一句含该串的句子）、finish[answer]（作答）6
FEVER（事实核查：SUPPORTS / REFUTES / NOT ENOUGH INFO）3
交互式决策ALFWorld（文本版家居任务环境）环境相关文本动作（134 个未见评测游戏）1–2
WebShop（模拟网购：按指令搜索并购买商品）搜索/点击等网页动作（500 条测试指令）1–2

基线包括：Standard（直接作答）、CoT、CoT-SC（自洽采样）、Act-only、监督式微调（BUTLER，模仿学习）与 RL 微调（BUTLER 在 ALFWorld 上）、IL / IL+RL（WebShop 上）以及人类表现。论文另在附录给出 GPT-3 上的补充实验与微调（finetuning）对照。

主要失效模式

  • ReAct：推理结构受格式约束，容易推理出错（47%）；当检索持续拿不到有用信息时会偏离任务；可能重复先前思考与动作、陷入循环——但几乎不产生幻觉（0%）；
  • CoT：失败主因是幻觉事实（56%），缺少外部信息校验；
  • Act-only：无法充分分解目标、易丢失环境状态、失败后难以恢复；
  • ReAct-IM（仅靠外部反馈的独白）：缺少高层目标分解与常识推理。
  • 缓解：与 CoT-SC 组合（内部/外部知识互补）；人在环编辑推理句纠正行为（图 3）。

影响与课程关联

  • 与第六讲的关系：CS329Z Lecture 6「Agent Design Patterns & Scaffolds」讲授 workflows-vs-agents 分类法、五种可组合工作流模式与智能体模式（ReAct、plan-and-execute、reflection）。ReAct 正是「智能体式循环」的原型：LLM 在循环中自主决定下一个动作，与 Anthropic《Building Effective Agents》（本专栏第二讲必读精讲）中的 agent 定义一脉相承。
  • 范式地位：ReAct 是「推理 + 工具调用」智能体的定名之作——今天几乎所有编码/搜索/计算机操作智能体的核心循环（模型输出思考与工具调用 → 环境返回观察 → 再思考）都是 ReAct 格式的工程化；第四讲的 function calling 可视为把 ReAct 的「行动」从文本约定升级为 API 原生能力。
  • 生态延续：DSPy（第五讲必读精讲）内建 dspy.ReAct 模块，把该模式变成可编译优化的组件；一作 Shunyu Yao 后续参与的 Tree of Thoughts、SWE-agent（第十五讲必读）等工作延续了「推理结构 × 环境交互」这条主线；WebShop 也出现在第十七讲（Frontiers & Open Problems）的扩展阅读中。
  • 工程启示：给智能体加显式思考步骤不只为可解释性——它实打实地降低幻觉、便于人在环干预；同时要为「检索失败/行动失败」设计回退路径（如 ReAct → CoT-SC），并防范重复循环（现代 scaffold 中的循环检测与步数上限即源于此）。
