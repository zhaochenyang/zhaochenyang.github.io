一句话总结：本文提出通用用户模型（General User Model, GUM）架构——通过观察用户与计算机的任意非结构化交互（如屏幕截图、系统通知），用多模态大模型持续构建并修订带置信权重的自然语言命题（confidence-weighted propositions），刻画用户的知识、偏好与情境；在其上构建的主动助手 GUMBO 能「主动发现并执行用户自己都想不到去请求的有用操作」。实验显示 GUM 推断准确（邮件场景 76.15%、屏幕场景 0.79）且置信度校准良好（Brier 0.17–0.28）。

背景与要解决的问题

"Human-computer interaction has long imagined technology that understands us... yet current user models remain fragmented, narrowly tailored to specific apps." 人机交互领域长久以来梦想着「能理解我们」的技术……然而现有的用户模型仍然是碎片化的、只为特定应用窄化定制的。

传统用户建模局限于单个应用内的信号（推荐系统的点击、IDE 内的操作），无法跨应用、跨情境地理解用户。本文要回答：能否只靠观察用户在计算机上的日常使用，就构建一个通用、可持续演化、可做校准推理的用户模型，并以此驱动下一代主动式（proactive）助手？这正是 CS329Z 第 16 讲「Proactive Agents」的核心议题——从被动响应转向主动预判。

核心观点

观点 1：用户模型 = 带置信权重的自然语言命题库

GUM 不用向量嵌入或固定 schema 存用户画像，而是把对用户的理解表达为自然语言命题（proposition），每条附带：置信度（1–10 打分归一化到 0–1）、衰减因子（1–10，表示命题随时间「变陈旧」的速率——「用户是博士生」衰减慢，「用户正在调试内存泄漏」衰减快）、支持它的底层观察、生成理由与时间戳。自然语言形式让用户可以直接查看、编辑、删除模型对自己的认知。

观点 2：从任意非结构化观察持续学习

输入是「任何可被大模型处理的观察」：macOS 上实现了 Screen Observer（监听键鼠活动、在输入时截屏、用视觉模型 Qwen 2.5 VL 72B 转成文本更新）与 Notification Observer（读取系统通知数据库）。观察是带来源、时间戳、唯一 ID 的事实记录；命题是从中做出的推断——两者分离保证了可追溯性。

观点 3：隐私审计前置（contextual integrity）

观察进入命题库之前先过 Audit 模块：基于 Nissenbaum 的情境完整性（contextual integrity）理论，用 GUM 已有命题推断用户的隐私预期，逐条判断「是否披露新信息？数据类型？主体是谁？接收方是谁？应否传入模型？」。工作邮件可保留；银行凭据、金融账号等敏感输入被阻止。

观点 4：主动助手的价值在于「用户想不到去请求」

"Proactively identify and perform actions that users wouldn't think to request explicitly." 主动识别并执行用户自己都想不到去明确请求的操作。

GUMBO 的高价值建议实例：根据用户的研究习惯生成 LaTeX 大纲、根据搬家相关信息制定搬迁计划、根据 Twitch 观看行为推荐相关主播、帮配置 Gmail 通知、给演示幻灯片提建议。是否打断用户采用 mixed-initiative（混合主动）决策：比较「打扰的期望效用」与「不打扰的期望效用」（综合建议有用概率、完成收益、错误打扰成本、错失帮助成本），另加 token-bucket 速率限制（最多每分钟 1 条建议）。

GUM 架构与流水线

阶段机制细节
Observe 观察Screen Observer（键鼠触发截屏，Qwen 2.5 VL 72B 视觉转写）+ Notification Observer（读系统通知库）；输出带来源/时间戳/ID 的事实记录
Audit 审计情境完整性过滤：用已有命题推断隐私预期，阻止敏感数据入库
Propose 生成先生成推理说明（观察与用户的关系）→ 自然语言命题 → 置信度（1–10 → 0–1）→ 命题级衰减因子（1–10）
Retrieve 检索BM25 词法检索 → 时间衰减调整（衰减分 × 年龄，k=2，按天计）→ MMR 多样性（λ=0.5）→ LLM 重排为 identical / similar / unrelated 三类；相同或相似触发修订
Revise 修订新旧命题冲突/强化时合并、改写或更新，重新生成置信度（可升可降）；置信度归零的命题不删除（保留透明性），仅默认查询不展示

模型选型：刻意优先开源、可本地部署——屏幕转写用 Qwen 2.5 VL 72B，命题/修订/审计/重排等文本推理用 Llama 3.3 70B；系统兼容任何支持 OpenAI ChatCompletions API 的指令跟随模型。GUMBO 的工具执行默认禁用外部工具，需要 Google 搜索或代码执行时才调用 Gemini 2.0 Flash，本地文件检索用 macOS Spotlight，Computer Use（Operator API）在评估中因太慢且不稳定而禁用。

应用接口：实例化 GUM（绑定一个指令跟随 LLM）→ 订阅观察流 → 自然语言查询命题与底层观察（查询参数可控制相关性/多样性权衡、时间范围、是否应用时间衰减）。三类应用：给聊天助手补充上下文、管理 OS 通知只浮现重要信息、跨应用适应偏好的交互式智能体。

实验结果与结论

评估一：邮件场景的准确性与校准（18 名参与者）

数据：每人 Gmail Primary Inbox 最近 200 封邮件（排除 Promotions/Social），按时间顺序喂给 GUM；对 30 条分层抽样命题做准确性判断与成对偏好排序。对比三个消融变体：

变体准确性用户偏好 win rateBrier 校准分
Full GUM（Propose+Retrieve+Revise）76.15 ± 5.850.618 ± 0.070.17 ± 0.03
No Retrieve（有修订、仅滑动窗口）73.28 ± 4.420.463 ± 0.070.36 ± 0.07
No Retrieve, Revise（裸生成）74.41 ± 7.810.420 ± 0.07—
  • 单条命题准确性差异不显著——各变体都能生成相当准的命题；完整架构的优势在偏好排序（win rate，Holm 校正后 p<0.05）与置信度校准（Brier 0.17 vs 0.36）。
  • 置信度打满 10 分的命题被参与者评为 100% 准确；参与者对命题准确性平均打分 6.47/7。

评估二：隐私审计模块

  • 180 条生成命题中仅 7 条被参与者标记为违反隐私预期；对情境完整性解释的认同度平均 6.06/7。
  • 「最佳审计判断」选择率：Full GUM 61.1% vs 无检索 22.2% vs 无修订 16.6%。
  • 系统检查确认命题中未出现逐字信用卡号/电话/地址；但仍发现越界案例：引用朋友姓名令用户惊讶、把钓鱼邮件误当成用户兴趣。

评估三：GUMBO 端到端屏幕观察（5 名参与者，5 天部署）

24 小时静默数据收集 + 4 天主动使用（IRB 出于风险考虑限最多 5 人，补偿 75 美元）。结果：命题准确性 0.79 ± 0.07，Brier 0.28 ± 0.04（误差主要来自欠自信 underconfident，而非过度自信）；25% 的建议被评为 strong/excellent（7 分量表 6–7 分）；20.69% 方向正确但执行失败；5 人中 2 人研究结束后仍想继续用、2 人截图保存了建议。

局限与伦理

  • 局限：样本小且偏技术用户（熟人网络招募）；仍会产生错误的高置信命题（幻觉/误归因，甚至虚构应用）；屏幕只是上下文的狭窄代理（手机、线下活动无法捕获）；执行能力不足（如声称设了提醒但实际没有通知 API 权限）；时机问题（建议过早、或建议用户已完成的事）；对压力/工作不满/能力的直白推断让部分用户觉得「被评判」（judgmental）。
  • 安全：垃圾邮件/钓鱼/广告可能污染命题库——论文称之为 「GUM injection」风险；防御手段包括对异常输入要求用户确认、类反垃圾过滤、红队测试；强烈建议 GUM 在用户本地或个人基础设施上运行，外部访问受控且可审计。
  • 伦理：可能被滥用于劝说、广告定向或监控；第三方可能在未获同意下训练用户模型；底层大模型的偏见会被放大；存在「隐私悖论」（口头重视隐私，系统越好用越愿意交数据）。

影响与课程关联

  • 与 CS329Z 第 16 讲（Proactive Agents）的关系：该讲主线是「从被动到主动」——GUM、Next Action Prediction、开源主动个人智能体、隐私与信任、何时主动发起 vs 等待（mixed initiative）。本文正是 GUM 概念的提出之作：它给出了主动智能体的「用户理解层」参考架构，其 mixed-initiative 打断决策与 token-bucket 限速是「何时该主动」的具体工程答案。
  • 与课程其他讲次的呼应：命题库的 Propose/Retrieve/Revise 循环是第 7 讲「记忆架构」（MemGPT/Mem0 的提取-整合-更新）在用户建模上的镜像；「GUM injection」对应第 14 讲安全主题中的间接 prompt injection 与隐私风险；置信度校准（Brier 分）呼应第 13 讲评估基础设施。
  • 领域意义：把「用户模型」从推荐系统的隐式嵌入升级为可解释、可编辑、可审计的自然语言命题库，为 OS 级主动助手（计算机使用智能体的个性化层）提供了一条兼顾能力与隐私的路径。
