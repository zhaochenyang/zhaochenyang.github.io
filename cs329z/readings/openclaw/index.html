一句话总结：OpenClaw 是目前规模最大的开源个人 AI 助手（GitHub 约 39 万 star、10 万+ commits、MIT 协议）：它运行在你自己的设备上，接入你已经在用的聊天渠道（WhatsApp、Telegram、Slack、Discord、iMessage 等 20+），状态/记忆/凭据全部留在本地硬件——是 CS329Z 第 16 讲「开源主动式个人智能体」的代表案例。

背景与要解决的问题

主流 AI 助手（ChatGPT、各家 Copilot）都是云端托管 + 被动应答模式：数据在别人的服务器上，交互被限定在官方 App/网页里，助手不会主动找你。OpenClaw 试图走另一条路：

  • 本地优先：助手跑在你自己的计算机上，个人笔记本助手与团队共享部署只是配置差异；
  • 渠道即界面：不强迫用户装新 App，而是「在你已经在用的聊天渠道里与你相见」；
  • 能真正做事：口号是 "The AI that really does things"——通过 tools、skills、plugins 操作真实设备与账户；
  • 独立治理：由独立 501(c)(3) 非营利基金会（OpenClaw Foundation）雇佣核心团队并签署发布；企业（Amazon、OpenAI、Red Hat、NVIDIA、Vercel 等）是捐赠者与基础设施支持方，而非所有者。
"Your assistant, on your devices, in your chats. — The AI that really does things. Any OS. Any Platform. The lobster way." 你的助手，在你的设备上，在你（已有）的聊天里。——真正能做事的 AI。任意操作系统、任意平台，「龙虾之道」。
"OpenAI is a donor, not an owner." OpenAI 是捐赠者，不是所有者。（README 对项目独立治理的明确声明）

核心观点

观点 1：隐私 = 数据不出本地硬件

OpenClaw 的隐私模型非常直白：状态、记忆、凭据都存在你的硬件上。外发的内容只有三类——你选择的模型提供方的推理请求、聊天平台消息本身、以及你主动开启的诊断导出。默认仅做每日版本检查；匿名功能统计是可选项，可用 update.checkOnStart: false 关闭。项目没有付费层、没有托管服务、没有代币。

"State, memory, and credentials live on your hardware." 状态、记忆与凭据都存在你的硬件上。

观点 2：Gateway 是本地控制平面

系统核心是一个叫 Gateway 的本地控制平面（control plane），统一管理会话、工具、事件与渠道连接。所有界面（Control UI 网页面板、CLI、TUI）都连接到 Gateway；Channels 把助手接入各消息平台；Companion apps / nodes（macOS、iOS、Android、Windows、Linux 原生应用）提供语音、Canvas 画布、摄像头、屏幕与设备本地操作能力。

观点 3：模型与能力都可插拔

OpenClaw 不绑定任何模型：托管与本地模型提供方均支持，Claude、Codex、本地模型等可作为插件替换；能力扩展通过 tools（工具）、skills（技能）、plugins（插件）与 ClawHub（社区能力市场）分发。这使它可以随模型生态演进而不被单一厂商锁定。

观点 4：安全模型——「可信网关、不可信执行、确定性策略」

README 用一句话概括安全理念：trusted gateway, untrusted execution, deterministic policy（可信网关、不可信执行、确定性策略）。具体守则：

  • 把入站消息当作不可信输入（提示注入防线，见第 14 讲）；
  • 支持 DM 的渠道默认对未知发送者启用配对（pairing），须批准配对请求才能对话；
  • 除非显式配置沙箱，工具默认在宿主机上运行——在接入其他用户或对外暴露 Gateway 之前，必须先读安全、暴露与沙箱文档。
"Treat inbound messages as untrusted input." 把（渠道）入站消息当作不可信输入来对待。

架构剖析

架构示意（据 README 文字整理）：中心是运行在用户设备上的 Gateway（本地控制平面：会话 / 工具 / 事件 / 渠道连接）。向外辐射三类连接：① Channels —— WhatsApp、Telegram、Slack、Discord、Google Chat、Signal、iMessage 等 20+ 消息平台；② Control UI / CLI / TUI —— 本地管理界面；③ Companion apps / nodes —— 各操作系统原生应用，提供语音、Canvas、摄像头、屏幕与设备本地操作。模型提供方（Claude / Codex / 本地模型）以插件形式接入 Gateway；能力经 tools / skills / plugins / ClawHub 扩展。

Channels接入消息平台20+ 渠道；未知发送者默认需配对批准
Companion apps / nodes设备本地能力macOS/iOS/Android/Windows/Linux；语音、Canvas、摄像头、屏幕操作
Control UI / CLI / TUI管理与调试界面onboarding 向导验证模型访问、创建工作区、配置 Gateway
模型插件推理提供方托管或本地模型；Claude、Codex 等可替换
tools / skills / plugins / ClawHub能力扩展新能力通常以插件形式经 ClawHub 分发

安装与运行要求

  • macOS / Linux / WSL2：官方 install.sh 一键脚本；Windows：PowerShell 执行 install.ps1；
  • 已有 Node.js 时可全局安装 npm 包 openclaw（要求 Node 24.16+ 或 26.1+，推荐 Node 26）；
  • 新安装自动进入 onboarding 向导；仓库为 pnpm workspace（开发需 pnpm，不能用根目录 npm install）。

影响与课程关联

  • 与课程的关联：CS329Z 第 16 讲「Proactive Agents」把 OpenClaw 列为开源主动式个人智能体的代表——它展示了主动智能体落地时的完整工程面：常驻 Gateway（能主动发起而非等待提示）、多渠道触达（在用户已有的通讯工具中出现）、设备本地操作（语音/屏幕/摄像头节点）。
  • 隐私与信任：第 16 讲讨论主动智能体的隐私与信任问题，OpenClaw 的「数据留在本地硬件 + 配对审批 + 沙箱选择」正是对该问题的一种工程回答；第 14 讲（Safety & Guardrails）的提示注入防线（入站消息视为不可信）在其安全模型中也有直接体现。
  • 生态意义：MIT 协议 + 基金会治理 + 插件化模型接入，为「个人拥有并控制自己的智能体」提供了可复制的开源范式。
