Towards Execution-Grounded Automated AI Research

迈向以执行为根基的自动化 AI 研究
Chenglei Si, Zitong Yang, Yejin Choi, Emmanuel Candès, Diyi Yang, Tatsunori Hashimoto（含 CS329Z 主讲教师 Diyi Yang）· arXiv:2601.14525 · 2026-01-20 · cs.CL / cs.AI / cs.LG

TL;DR 背景与问题 系统：自动想法执行器 LLM 研究员基准测试 方法一：演化搜索 方法二：执行奖励 RL 分析与结论 局限 影响与关联 术语对照
一句话总结：LLM 能提出「看起来合理但未必有效」的研究想法——本文造了一个自动想法执行器（automated idea executor），把 LLM 预训练（nanoGPT）与后训练（GRPO 微调 Qwen2.5-Math-1.5B）变成可自动执行实验的研究环境，并比较两种利用执行反馈的方式：执行引导的演化搜索（10 轮内即超基线：后训练 69.4% vs 48.0%，预训练 19.7 分钟 vs 35.9 分钟）与执行奖励强化学习（平均奖励上升但上限不升、发生模式坍缩）。结论：闭环「提想法 → 真实执行 → 用结果筛选/进化」是自动化 AI 研究的可行路径，其中演化搜索显著优于 RL。

背景与要解决的问题

"Automated AI research holds great potential to accelerate scientific discovery... [but] current LLMs often generate plausible-looking but ineffective ideas." 自动化 AI 研究有加速科学发现的巨大潜力……但当前 LLM 经常生成「貌似合理却无效」的想法。

现有「AI 研究员」类工作（让 LLM 写研究提案、生成 idea）的致命短板是缺少真实验证：想法以自然语言表达，没人真的把它实现成代码、跑在 GPU 上、用实验结果说话。本文的三个递进问题：

  1. 能否把开放式 AI 研究变成可大规模自动执行的环境？（→ 自动想法执行器）
  2. 前沿 LLM 作为「想法提出者（ideator）」与「想法实现者（executor）」的能力如何？（→ 基准测试）
  3. 模型能否从执行反馈中学习，提出更好的想法？（→ 演化搜索 vs RL 两条路线）

实验选择两个真实且 GPU 密集的任务：LLM 预训练（基于 nanoGPT speedrun）与LLM 后训练（基于 GRPO 算法的数学推理微调）。

系统与架构：自动想法执行器

图 1（详见原文 Figure 1）：自动想法执行器由 Implementer（实现）、Scheduler（调度）、Worker（执行）三类组件构成；执行结果作为奖励信号，驱动演化搜索与 RL 两种学习回路，学习过程中只更新 ideator（想法提出者）模型。

三个组件

  • Implementer（实现器）：接收一批自然语言想法；对每个想法调用代码执行 LLM，结合基线代码库生成 diff（并行采样 10 个）；patch 失败时把错误日志回传模型自我修正（最多 2 轮），取第一个能成功应用的 diff；修补后的代码库打包上传云端。
  • Scheduler（调度器）：定期从云端拉取新代码库，检查资源需求，生成任务配置并提交到可用 GPU。
  • Worker（执行器）：在 GPU 上跑实验；成功则把日志与指标上传 wandb，并保存想法文本、代码修改、执行日志等元数据；失败（如代码错误）则终止并记录。

这套「自然语言想法 → 代码 diff → 真实 GPU 实验 → 指标回传」的流水线，就是标题中 execution-grounded（以执行为根基）的含义：一切想法最终由真实实验结果裁决。

基准测试：LLM 当研究员的能力如何

先测「自产自销」（同一模型既提想法又实现想法），每环境采样并执行 50 个想法：

  • 执行成功率：Claude-4.5-Opus 与 Claude-4.5-Sonnet 显著高于 GPT-5；预训练环境中两个 Claude 模型的执行成功率都超过 90%。
  • Best-of-50 已能超基线：GRPO 环境 Claude-4.5-Sonnet 最高准确率 60.4%（基线 48.0%）；nanoGPT 环境 Claude-4.5-Opus 最低验证损失 3.237（基线 3.255）。
  • 换人实现会掉链子：固定 GPT-5 当 executor 时，各家 ideator 的想法执行成功率约 42%–78%；Claude-4.5-Sonnet 的想法自己执行成功率 84%/90%，交给 GPT-5 只有 42%/78%——想法的「可执行性」与实现者强相关。
  • 开源模型也能打：Qwen3-235B 的想法在 GRPO 上最高 50.2%、nanoGPT 上最低损失 3.238，均超基线。

方法一：执行引导的演化搜索（Execution-Guided Evolutionary Search）

机制（无需梯度更新）

  1. 第 0 轮采样一批初始想法并执行，得到 (idea, reward) 轨迹；
  2. 之后每轮的生成分两路：exploitation（利用）——挑选历史上超过基线的正向想法，让模型生成「结合这些优点」的新变体；exploration（探索）——随机抽取历史想法作上下文，要求生成与之不同的新想法；
  3. 初始 50%/50% 分配，随后逐轮降低探索比例、提高利用比例；
  4. 每轮执行新想法、累积轨迹。批大小：GRPO 环境 50、nanoGPT 环境 80。

主结果（Table 1）

Baseline（GRPO / nanoGPT speedrun）48.0%35.9 分钟

  • 后训练：Claude-4.5-Sonnet 在第 2 轮就找到 69.4% 的方案，超过了人类专家最佳（68.8%）。该方案的洞见颇有研究价值：在此设定下，去掉 importance reweighting 与 clipping 的朴素策略梯度 + 组内平均基线，反而优于标准 GRPO 目标。
  • 预训练：Claude-4.5-Opus 第 9 轮达到最低验证损失 3.1407；其方案组合了架构修改 + 超参调整 + 对中间检查点做 EMA，在 8×H100 复现 speedrun 设定时 19.7 分钟达标（基线 35.9 分钟）——但与人类最佳 2.1 分钟仍差距很大。
  • 对比 Best-of-N：相同采样预算下，演化搜索从第 1 轮起就显著优于 best-of-N（GPT-5，N=80/160/240）——价值不在多采样，而在利用历史轨迹迭代改进。

想法质量分析（Table 2）

把想法分为「超参类」与「算法类」：所有模型生成的想法都以算法类为主（GPT-5 约 95%/85%，Claude-4.5-Opus 约 96%/91%），说明模型不是在变相调参；多数最佳结果来自算法类想法。Claude-4.5-Sonnet 的超参类想法占比明显更高（GRPO 环境 41.1%），其最佳 GRPO 结果恰好也来自超参精调。作者还观察到：部分生成想法与近期论文高度相似，说明模型的想法空间已接近研究前沿。

方法二：执行奖励强化学习（RL from Execution Reward）

设置

  • 基座：Qwen3-30B-A3B；算法：标准 GRPO；提示中给出基线代码库，要求提出改进想法（先输出 thinking trace，再输出自然语言想法；只把想法送执行器，最长 8192 tokens）。
  • 奖励：执行成功 → 后训练环境用验证准确率、预训练环境用验证损失倒数；执行失败 → 0。
  • 并行规模：后训练 group size 256（每想法 1 GPU，共 256 GPU）；预训练 group size 128（每想法 8 GPU，共 1024 GPU）。

结果与训练动态

  • 平均奖励上升：GRPO 环境平均准确率 0.253 → 0.343（40 轮）；nanoGPT 环境平均奖励 0.194 → 0.246（68 轮，对应平均验证损失 5.150 → 4.066）。
  • 最大奖励不升：每轮最佳值没有清晰上升趋势——而科学发现恰恰关心上限而非平均水平。
  • 思考变短：thinking trace 长度快速下降（长思考的想法执行成功率更低，模型学会「少想多得分」），idea 本身长度基本稳定。
  • 多样性坍缩（mode collapse）：nanoGPT 环境中模型收敛到两个「万金油」想法——用 LayerNorm 替换 RMSNorm、对检查点做 EMA；这两类想法占比从第 0 轮的 51/128 升到第 68 轮的 119/128。
  • 附录还报告了三次补救尝试（dynamic prompt、length reward、diversity reward），均未从根本上解决上限不升的问题。

核心结论

"Execution-guided evolutionary search is sample-efficient... Reinforcement learning from execution reward, on the other hand, suffers from mode collapse. RL causes the ideator model to converge on a few easy-to-implement ideas." 执行引导的演化搜索是样本高效的……而以执行奖励做强化学习则 suffer 于模式坍缩：RL 使想法生成模型收敛到少数几个「容易实现」的想法上。
  • 可行性：前沿 LLM 已能在真实、开放式的 LLM 研究任务中自动实现并执行大量想法，执行反馈闭环成立。
  • 路线比较：有限预算下找高质量方案 → 演化搜索（利用历史、样本高效、10 轮内超基线甚至超人类专家）；提高平均可靠性 → RL，但以牺牲多样性与上限为代价。
  • 对「AI 做科研」的启示：只优化平均奖励不足以产生突破——科研要的是高上限的想法；探索激励与多样性维持是 RL 路线的核心待解问题。

局限性（原文 Discussion）

  1. 泛化性未验证：小规模环境里有效的想法，未必能扩展到更大模型、更长训练或其他数据集。
  2. RL 只提平均不提上限：训练目标缺探索激励、基础想法多样性不足。
  3. 执行器能力圈定搜索空间：需要外部库、辅助模型或系统级优化的复杂想法常无法自动执行，带来奖励噪声。
  4. 奖励单一：只用「有效性」，未纳入新颖性、趣味性等科研价值维度。
