MemGPT: Towards LLMs as Operating Systems

MemGPT：迈向「把 LLM 当作操作系统」的智能体记忆架构
Charles Packer, Sarah Wooders, Kevin Lin, Vivian Fang, Shishir G. Patil, Ion Stoica, Joseph E. Gonzalez（UC Berkeley）· arXiv:2310.08560 · 2023

一句话总结：MemGPT 借鉴操作系统的虚拟内存分页（virtual memory paging）思想，提出「虚拟上下文管理（virtual context management）」：把 LLM 的上下文窗口当作「物理内存」、外部存储当作「磁盘」，让 LLM 通过函数调用自主管理自己的记忆（何时写入、何时检索、何时逐出），从而在固定上下文窗口下获得「无限上下文」的错觉——在多会话聊天与文档分析两类任务上显著超越固定上下文基线（如深度记忆检索准确率 GPT-4 从 32.1% 提升到 92.5%）。

背景与要解决的问题

LLM 受限于固定长度的上下文窗口：论文发表时（2023 年底至 2024 年初）常用模型的上下文从 Llama 的 2k token 到 GPT-4 Turbo 的 128k token 不等，只能容纳几十轮到几百轮对话消息。这直接限制了长对话（跨周、跨月的陪伴/助理型智能体）与长文档分析（如动辄超过百万 token 的 SEC 年报）两类任务。

作者指出，单纯扩大上下文窗口并非出路：

  • self-attention 的计算与显存开销随上下文长度平方级增长；
  • 即使克服算力问题，已有研究（Liu et al. 2023，即「Lost in the Middle」）表明长上下文模型难以有效利用额外上下文——对窗口中部信息的召回明显偏弱；
  • 训练前沿 LLM 成本巨大，而上下文扩展的收益递减。

因此论文研究的核心问题是：如何在使用固定上下文模型的前提下，提供「无限上下文」的错觉？答案来自操作系统：当年虚拟内存分页技术让应用能够操作远超物理内存的数据集——在内存与磁盘之间换入换出数据。MemGPT 把这一思想搬到 LLM 上。

核心观点

观点 1：上下文窗口 = 受限的内存资源，应设计「LLM 的内存层级」

"In MemGPT, we treat context windows as a constrained memory resource, and design a memory hierarchy for LLMs analogous to memory tiers used in traditional OSes." 在 MemGPT 中，我们把上下文窗口视为一种受限的内存资源，并为 LLM 设计一套与传统操作系统内存层级类似的记忆层级。

对应关系：main context（主上下文，≈ 物理内存/RAM）即 LLM 的 prompt tokens，推理时可直接访问；external context（外部上下文，≈ 磁盘）是上下文窗口之外的存储，必须显式移入主上下文才能被 LLM 看到。

观点 2：记忆管理完全由 LLM 自主驱动（self-directed），靠函数调用实现

"Memory edits and retrieval are entirely self-directed: MemGPT autonomously updates and searches through its own memory based on the current context." 记忆的编辑与检索完全是自主的：MemGPT 基于当前上下文，自主更新并搜索自己的记忆。

这正是 CS329Z 第七讲「记忆作为工具动作（memory as tool-based actions）」的代表性方案：LLM 通过函数调用读写外部数据源、修改自身上下文、并决定何时向用户返回响应。系统提示中写明内存层级的用途说明与函数 schema，让模型「知道如何操作自己的记忆」。

观点 3：内存压力警告 + 逐出策略，防止上下文溢出

当 prompt tokens 超过「警告阈值」（如上下文窗口的 70%），队列管理器会向上下文插入一条内存压力（memory pressure）系统警告，提示 LLM 主动把 FIFO 队列中的重要信息存到工作上下文或归档存储；当超过「刷新阈值」（如 100%），队列被逐出（如清掉 50%），并生成递归摘要——被逐出的消息永久保存在 recall storage 中，可随时通过函数调用检索回来。

观点 4：事件驱动控制流 + 函数链（function chaining）

MemGPT 中事件触发推理：用户消息、系统消息（容量警告）、用户交互事件（登录提醒、文档上传完成）、定时事件（允许「无提示」自主运行）都会转化为文本追加进主上下文。函数调用可携带特殊标志 request_heartbeat=true，请求函数执行完后立即返回处理器继续推理，从而把多个函数链式串联——这是 MemGPT 能做多步检索（如分页翻查、多跳查询）的关键机制。

方法与架构

双层记忆结构

层级组成类比说明
Main context（主上下文 = prompt tokens）System instructions（系统指令）物理内存 / RAM只读静态：控制流说明、各记忆层用途、函数使用指南
Working context（工作上下文）固定大小的可读写文本块（仅能通过函数调用修改），存放用户关键事实、偏好与智能体人设
FIFO queue（先进先出消息队列）滚动消息历史（用户/智能体消息、系统消息、函数输入输出）；队首第一条是已被逐出消息的递归摘要
External context（外部上下文）Recall storage（回忆存储）磁盘完整消息数据库，可检索调回
Archival storage（归档存储）任意长度文本对象的读写数据库（实验中用 PostgreSQL + pgvector 向量检索、HNSW 索引）
原文图 3（系统架构图）要点：固定上下文的「LLM 处理器」被增强了一个分层记忆系统与一组管理自身记忆的函数。LLM 的 prompt tokens（主上下文）由系统指令、工作上下文、FIFO 队列三段拼接；LLM 的 completion tokens（输出）被「函数执行器」解析为函数调用；函数负责在主上下文与外部上下文（归档/回忆存储）之间搬运数据；执行结果（包括运行时错误，如上下文已满仍尝试写入）会反馈回处理器，形成「从行动中学习并调整行为」的闭环。检索机制自带分页（pagination），防止一次检索撑爆上下文。

队列管理器（Queue Manager）的工作流

  1. 新消息到达 → 追加进 FIFO 队列 → 拼接 prompt tokens → 触发 LLM 推理；
  2. 入站消息与 LLM 输出都写入 recall storage（消息数据库）；
  3. 通过函数调用检索到的历史消息被追加到队尾，重新进入上下文；
  4. 超过警告阈值 → 插入「内存压力」系统消息，给 LLM 机会先保存重要信息；
  5. 超过刷新阈值 → 逐出一部分消息并用「已有递归摘要 + 被逐出消息」生成新的递归摘要。

实验结果与结论

评测围绕两类「上下文受限最严重」的领域：会话智能体（扩展的 Multi-Session Chat 数据集，一致性 + 参与度两个维度）与文档分析（多文档问答 + 新提出的嵌套键值检索）。基线为固定上下文模型（GPT-3.5 Turbo / GPT-4 / GPT-4 Turbo），MemGPT 分别搭载这三种底层模型对比。

1. 深度记忆检索 DMR（一致性）

智能体被问及此前 5 个会话中讨论过的具体话题。基线只能看到过去对话的有损摘要；MemGPT 可分页检索完整历史。

2. 会话开场白（参与度）

评测智能体能否利用长期积累的用户知识生成有参与感的开场白：MemGPT（GPT-4 底座）与金标人设的相似度 SIM-1 达 0.868，与人类手写开场白的表现相当甚至更高；其开场白往往比人类基线更详尽、覆盖更多人设信息。工作上下文（working context）中的信息存储是生成高质量开场白的关键。

3. 多文档问答（NaturalQuestions-Open）

固定上下文基线的表现被检索器「封顶」——若嵌入检索没把金标文档排进 top-K，基线永远看不到它；而 MemGPT 可对归档存储多次调用、分页翻查，可用文档总量不再受上下文窗口限制，性能不随有效上下文长度增加而衰减。文中也如实报告局限：MemGPT 有时会在翻完检索结果前「提前停止分页」；GPT-3.5 底座因函数调用能力弱导致性能明显退化，GPT-4 底座效果最佳（有趣的是 MemGPT+GPT-4 反而好于 MemGPT+GPT-4 Turbo）。

4. 嵌套键值检索（Nested KV，新任务）

140 组 128-bit UUID 键值对（约 8k token），值本身可能又是键，需要多跳查找（嵌套 0–4 层）。结果：GPT-3.5 在 1 层嵌套即跌到 0%（典型失败：直接返回原值）；GPT-4 与 GPT-4 Turbo 到 3 层嵌套也归零；MemGPT + GPT-4 完全不受嵌套层数影响——通过反复函数查询主上下文中的键值对完成多跳查找，是嵌套超过 2 层后唯一能稳定完成任务的方案。

结论

"MemGPT demonstrates that operating system techniques like hierarchical memory management and interrupts can unlock the potential of LLMs even when constrained by fixed context lengths." MemGPT 证明了分层内存管理、中断等操作系统技术，即使在固定上下文长度的约束下，也能释放 LLM 的潜力。

影响与课程关联

  • 领域地位：MemGPT 是「智能体记忆架构」方向的奠基之作，把 OS 的虚拟内存/分页/中断概念系统性地引入 LLM 智能体设计；作者团队（UC Berkeley Sky Lab，Ion Stoica / Joseph Gonzalez 组）随后创立 Letta 公司，将 MemGPT 发展为开源智能体框架（本讲扩展阅读 Letta《Agent Memory》即其工程化续篇）。
  • 与 CS329Z 第七讲的关联：第七讲「Agent Memory Architectures」讨论短期/长期记忆、记忆作为工具动作、文件系统作为外化记忆等主题——MemGPT 的「LLM 通过函数调用自主读写分层记忆」正是「记忆即工具」的原型；其内存压力警告与递归摘要对应「上下文工程」中的清退与压缩策略。
  • 后续发展：与生成式智能体（Generative Agents 的记忆流 + 反思）、Mem0（生产级可扩展长期记忆）等共同构成智能体记忆研究谱系；「上下文窗口像 RAM、外部存储像磁盘」的类比已成为智能体工程的标准心智模型。
