SWE-smith: Scaling Data for Software Engineering Agents

SWE-smith：为软件工程智能体规模化生成训练数据

一句话总结：SWE-smith 提出「先建执行环境、再合成任务」的逆向思路：对任意 Python 仓库自动注入 bug 并用测试套件验证（只保留真正弄坏测试的补丁），以约 $1,360 成本从 128 个 GitHub 仓库合成 5 万条软件工程任务；用 Claude 3.7 Sonnet 专家轨迹做拒绝采样微调（rejection sampling fine-tuning）训练出的 SWE-agent-LM-32B 在 SWE-bench Verified 上达 40.2% Pass@1，创当时开源权重模型最优。

背景与要解决的问题

软件工程智能体（能解决 GitHub issue 的编码 agent）的训练数据稀缺且收集昂贵：已有数据集要么规模小（SWE-gym 2.4k、R2E 0.25k），要么环境体积庞大（R2E-Gym 子集 4TB、SWE-gym 6TB），要么需要大量人工整理。SWE-bench 式的「从真实 PR 收集任务」路线要求每个任务对应一个可复现的历史环境，作者估计若照此方式做 5 万实例，环境存储可能需要 50–150TB——比 SWE-smith 的 295GB 大约 500 倍。

本文的核心洞察是把方向反过来：

"define an execution environment first" 先定义一个执行环境（而不是先找任务再建环境）——然后在环境里批量合成任务。

核心观点

观点 1：bug 可以自动「制造」，测试套件就是免费的验证器

给定一个测试基本全绿的仓库，向代码注入缺陷后运行测试：只有真正破坏一个或多个原本通过测试（Fail-to-Pass，F2P）的补丁才被保留为有效任务。这样每条合成任务天然自带「问题描述 + 复现测试 + 可验证的成功标准」，无需任何人工标注。

"break one or more existing, passing tests" （有效 bug 补丁的筛选标准：）使一个或多个原本通过的测试失败。

观点 2：问题描述（issue 文本）也可以由 LM 生成

每条任务配一段仿 GitHub issue 的文字，由 LM 根据 diff 补丁 + 一个随机 F2P 测试的源码 + 带 bug 运行测试的输出 生成（含复现代码）。消融显示「LM 生成的 issue 文本能有效逼近真实 issue」——用 LM 生成 issue 训练的模型（7.7%）与用原始真实 issue 训练的模型（7.8%）效果几乎相同；反而直接把 F2P 测试文本喂给专家会「泄露答案」，导致学生模型很少自己写复现脚本（复现尝试从 379 次跌到 127 次，降 66%）。

观点 3：数据规模与仓库多样性可以廉价扩展

5 万实例、128 个仓库、平均每仓库 381 条任务（最多的 pandas 达 2,277 条）；总成本约 $1,360（$1,000 生成 bug + $160 自动装环境 + $200 生成 issue），单条 issue 平均仅 2.54 美分。消融还发现：训练仓库数从 4 → 100 时下游性能大致按对数增长；针对单一仓库（SymPy）专用微调能大幅提升该仓库成绩（13.6% → 21.2%；在 SWE-agent-LM-32B 上 33.3% → 42.4%），且泛化损失很小。

观点 4：与 SWE-bench / SWE-agent 生态无缝衔接

SWE-smith 复用了 SWE-agent 来自动安装仓库（每仓库最多 100 步，要求 >80% 已有测试通过，人工仅约 7 分钟/仓库核对，全程约一位作者 20 小时），产出的任务实例、环境、轨迹与模型全部开源（swesmith.com），并新提出覆盖 9 种额外语言的 SWE-bench Multilingual（300 实例）。

方法与管道

四阶段任务创建流程

  1. 建环境：从 2024-11-18 PyPI 下载量前 5,000 的包中按 GitHub star 排序筛选（去掉 <1000 star、12 个 SWE-bench 测试仓库，确保许可证允许），用 SWE-agent 自动安装并跑测试，制作 Docker 镜像；
  2. 生成候选补丁：用四类 bug 注入策略产出候选 .diff；
  3. 执行验证：应用补丁、跑测试套件（限时 2 分钟），仅保留破坏 F2P 测试的补丁；总体候选合格率 50.1%；
  4. 生成 issue 文本：LM 基于补丁 + F2P 测试源码 + 失败输出写出仿 GitHub issue。

训练流程：拒绝采样微调

  1. 从 SWE-smith 抽任务子集（共尝试 8,686 个唯一实例，占数据集 17.3%）；
  2. 专家模型（主要为 claude-3-7-sonnet-20250219）在 SWE-agent 系统内跑轨迹（最多 75 步、成本上限 $2.00），总体解决率 36%（17,906 次尝试）；
  3. 只保留成功轨迹，每个任务最多 3 条，最终训练集 5,016 条轨迹；
  4. 微调学生模型 Qwen-2.5-Coder-Instruct 7B / 32B，推理同样最多 75 步、温度 0.0。

关键消融

  • bug 策略（各约 500 条轨迹）：PR Mirror 9.2% > LM Rewrite 8.8% ≈ Procedural 8.6% ≫ LM Modify 5.7%——「真实 PR 的镜像 bug」训练价值最高；
  • issue 来源：原始 issue 7.8% ≈ LM 生成 7.7% > F2P 测试文本 7.3% > 固定模板 6.4%；
  • 难度：专家解决率随难度递减（easy 58.6% / medium 41.0% / hard 17.0%），但训练难度与下游性能无明显单调关系；
  • 行为分析：SWE-agent-LM-32B 平均 24.9 步解决任务（比 Claude 3.7 Sonnet 的 29.1 步更短）；主要失败模式是重复动作——超过 25% 的失败轨迹含长度 ≥10 的重复序列（对应 89% 失败概率），其中 73% 是反复 view 同一文件；53% 的未解决实例因成本/步数/时限被截断，且主要卡在定位（localization）阶段。

影响与课程关联

  • 课程关联：CS329Z 第 11 讲「Data Selection & Quality」的主题——寻找信息量最大的数据、过滤与选择策略、从 agent 轨迹构建数据集——SWE-smith 是「从合成 + 执行验证中规模化造数据」的标杆案例：测试套件充当免费验证器，拒绝采样充当质量过滤器。
  • 与相邻讲次：训练用专家轨迹 + 拒绝采样对应第 10 讲（traces/demonstrations）；SWE-bench 与 4-tuple 评测框架对应第 12 讲；SWE-agent 架构对应第 15 讲 Coding Agents（该讲必读即 SWE-agent 与 OpenHands 论文）。
  • 团队与生态：作者阵容即 SWE-bench / SWE-agent 原班人马（John Yang、Kilian Lieret、Carlos Jimenez、Ofir Press、Diyi Yang——后两位/CS329Z 讲师 Diyi Yang 均为本课程讲师，John Yang 亦为课程讲师），SWE-smith 与 SWE-bench、SWE-agent 构成「评测—数据—智能体」完整开源生态；「先环境后任务」的逆向合成思路已被后续多个 agent 训练数据集借鉴。
