OpenHands: An Open Platform for AI Software Developers

OpenHands：面向 AI 软件开发者智能体的开放平台

TL;DR 背景与问题 核心观点 平台架构 评测与结论 影响与课程关联 术语对照
一句话总结：OpenHands（前身 OpenDevin）是一个 MIT 许可的开源 AI 软件开发智能体平台：智能体可以写代码、执行命令行、浏览网页，在沙箱化 Docker 运行时中安全操作；平台以事件流（event stream）为中心统一动作与观察，内置 10+ 种可插拔智能体、多智能体协作（委派）、聊天式 GUI 与 15 个评测基准的评测设施，由超过 188 位贡献者、2.1K+ 次贡献的社区共同建设。

背景与要解决的问题

「AI 软件开发者」类智能体（如 Devin、SWE-agent）需要同时具备多种能力：在真实环境中执行代码、操作文件系统、调用命令行、浏览网页、与用户交互。研究者与开发者若要从零搭建这样一套系统，需要处理沙箱安全、状态管理、前后端分离、评测复现等大量与智能体算法无关的基础设施问题。

OpenHands 的目标是把这些基础设施做成开放平台，让社区可以：（a）在统一框架下实现和比较新智能体；（b）在沙箱环境中安全地让智能体执行代码；（c）支持多智能体协作；（d）直接集成主流评测基准。项目 2024 年以 OpenDevin 之名发起（对标闭源 Devin），后更名 OpenHands，累积约 32K GitHub stars。

核心观点

观点 1：以「事件流」为中心的统一抽象

平台的核心状态是一条事件流（event stream）：所有历史动作（action）、观察（observation）、用户输入，以及成本统计与多智能体委派信息，都汇入这一条流。智能体的每一步是「读事件流 → 生成下一个动作」，环境把执行结果作为观察追加回流中。这一抽象使得任意智能体、任意运行时、任意前端都可以在同一协议下组合。

"OpenHands includes an agent hub with over 10 implemented agents." OpenHands 内置一个「智能体集线器」，收录了超过 10 种已实现的智能体。

观点 2：代码执行必须沙箱化

让 LLM 执行任意代码/命令存在真实风险。OpenHands 为每个任务启动隔离的 Docker 容器作为运行时（runtime），容器内提供 REST API 封装的三类执行环境：bash shell、Jupyter/IPython、Chromium（Playwright 驱动）浏览器，并支持自定义镜像。智能体只通过 API 与沙箱交互，宿主机不受影响。

观点 3：多智能体协作与社区共建

"OpenHands allows interactions between multiple agents as well." OpenHands 同样支持多个智能体之间的交互。

通过 AgentDelegateAction，一个智能体可以把子任务委派给另一个更专长的智能体（如把网页浏览交给 BrowsingAgent）。论文强调这是一个跨越学界与产业的社区项目：

"OpenHands is a community project spanning academia and industry." OpenHands 是一个横跨学术界与工业界的社区项目。

平台架构

层内容
动作原语IPythonRunCellAction（执行 Python 单元）、CmdRunAction（bash 命令）、BrowserInteractiveAction（浏览器操作）、AgentDelegateAction（委派其他智能体）、MessageAction（与用户对话）、AgentFinishAction（结束任务）
观察类型命令/代码执行输出、用户消息、浏览器状态（DOM、可访问性树、截图、标签页信息）
运行时（Runtime）每任务一个隔离 Docker 容器；内部 REST API 提供 bash、Jupyter/IPython、Chromium/Playwright；支持自定义镜像；镜像构建有独立工作流（按需叠加依赖层）
智能体集线器10+ 种智能体：CodeActAgent（主力，用 Python 代码作为统一动作空间）、BrowsingAgent（网页浏览）、GPTSwarm Agent（图式多智能体）、Micro Agent(s)（针对特定任务的轻量智能体）等
技能库（AgentSkills）可复用的 Python 辅助函数：edit_file、scroll_up/scroll_down、parse_image、parse_pdf 等——与 SWE-agent 的 ACI 思想一脉相承
前端聊天式 GUI，实时展示文件、命令、浏览器活动；用户可随时插话、纠正、中断
评测设施内置对 15 个基准的支持（见下节），统一复现流程

评测与结论

论文用 15 个基准展示平台能力，覆盖软件工程、网页浏览与通用任务：SWE-Bench、HumanEvalFix、BIRD、BioCoder、ML-Bench、Gorilla APIBench、ToolQA、WebArena、MiniWoB++、GAIA、GPQA、AgentBench、MINT、Entity Deduction Arena、ProofWriter。关键数字（gpt-4o-mini / gpt-4o / Claude 3.5 Sonnet）：

基准智能体结果
SWE-Bench LiteCodeActAgent v1.86.3 / 22.0 / 26.0
WebArenaBrowsingAgent v1.08.5 / 14.8 / 15.5（经委派协作：8.3 / 14.5 / 15.3）
HumanEvalFixCodeActAgent79.3
GPQA diamond—52.0
GAIA L1（validation）GPTSwarm30.2 / 32.1
MiniWoB++ / AgentBench-OS / MINT-math—40.8 / 57.6 / 77.3

结论：OpenHands 证明了「统一的开放基础设施」足以支撑从软件修复到网页操作的多类智能体研究与开发；平台本身（事件流 + 沙箱运行时 + 智能体集线器 + 评测集成）是论文的主要贡献，而非某个单点算法。

影响与课程关联

  • 领域地位：OpenHands 是最活跃的开源软件智能体平台之一（约 32K stars、188+ 贡献者、MIT 许可），其事件流架构与沙箱运行时设计被广泛借鉴；CS329Z 讲师 John Yang 与 OpenHands 社区关系密切（本讲扩展阅读《Don't Sleep on Single-agent Systems》即发表于 OpenHands 博客）。
  • 与课程的关联：CS329Z 第 15 讲以 SWE-agent 与 OpenHands 为两大必读，对应主题「OpenHands architectures」——比较「专用 ACI 脚手架」（SWE-agent）与「通用平台」（OpenHands）两种路线；平台中的 AgentSkills 与运行时隔离也呼应第 4 讲工具设计与沙箱、第 8 讲多智能体委派。
  • 工程启示：做智能体产品时，「执行环境的安全性」与「状态/事件的可回放性」是必须前置设计的基础设施；把动作空间统一到「写代码执行」（CodeAct）是一种强有力的通用化手段。
