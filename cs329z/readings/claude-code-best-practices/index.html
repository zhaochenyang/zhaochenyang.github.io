Claude Code: Best Practices for Agentic Coding

一句话总结：Claude Code 是 Anthropic 推出的命令行智能体编程工具（agentic coding），刻意保持「低层、不强制工作流」的设计；这篇官方最佳实践（作者 Boris Cherny）汇总了 Anthropic 内部团队与社区验证有效的使用模式——调优环境（CLAUDE.md）、扩展工具（MCP/斜杠命令）、常见工作流（先探索再规划再编码、TDD、视觉迭代）、优化交互（具体指令、及时纠偏、/clear 管理上下文）、headless 自动化、多 Claude 并行。

背景与要解决的问题

Claude Code 于 2025 年初作为研究项目发布，让 Anthropic 的工程师与研究者以更原生的方式把 Claude 融入编码流程。它的设计哲学是：

"Claude Code is intentionally low-level and unopinionated, providing close to raw model access without forcing specific workflows." Claude Code 刻意保持低层、不带成见，提供接近原始模型能力的访问，而不强制任何特定工作流。

这种灵活性带来了「幂器」般的可定制性与可脚本化能力，但也意味着新手面临陡峭的学习曲线——在形成自己的最佳实践之前容易用不好。本文正是为此而写：给出经过 Anthropic 内部与外部工程师验证的通用模式，同时强调「没有一条是金科玉律」，鼓励读者实验出适合自己的用法。

核心观点

观点 1：上下文是最需要管理的资源

Claude Code 会自动把上下文拉进 prompt，这既花时间也花 token。因此几乎所有实践都围绕「让模型在对的时刻拿到对的信息」展开：用 CLAUDE.md 提供持久项目上下文、用 /clear 在任务间重置上下文、用子代理（subagent）隔离调研过程、用 checklist/scratchpad 文件外化复杂任务状态。

观点 2：先探索、再规划、后编码（Explore → Plan → Code → Commit）

这是文中最重要的通用工作流：先让 Claude 读相关文件/图片/URL（明确告诉它「先别写代码」，复杂问题可派 subagent 调研以节省上下文）；再让它制定计划——此处推荐用「think」触发扩展思考（extended thinking），且思考预算按关键词分级：

"These specific phrases are mapped directly to increasing levels of thinking budget in the system: 'think' < 'think hard' < 'think harder' < 'ultrathink.'" 这些短语直接映射到系统中递增的思考预算等级：think < think hard < think harder < ultrathink。

计划满意后可以让 Claude 把计划写成文档或 GitHub issue（以便实现不满意时回退到这个点）；然后实现代码；最后提交并开 PR、更新 README/changelog。文中强调：跳过前两步，Claude 会倾向于直接跳到写代码；对需要深思的问题，先调研规划能显著提升表现。

观点 3：给 Claude 一个可迭代的「靶子」

"Claude performs best when it has a clear target to iterate against—a visual mock, a test case, or another kind of output." 当有一个清晰的目标可供迭代时——视觉稿、测试用例或其他形式的预期输出——Claude 的表现最好。

由此衍生出两个高频工作流：TDD（写测试→提交→写代码→迭代→提交）与视觉迭代（实现设计→截图→对比→修改）。视觉迭代通常 2–3 轮后效果明显好于第一版。

观点 4：指令越具体，纠偏越少

「Claude 能推断意图，但不会读心术。」文中给出 poor/good 指令对照，例如把 add tests for foo.py 改为「为 foo.py 写一个新测试，覆盖用户已登出的边界情况，不要用 mock」。此外：多给图片（设计稿、图表、截图，macOS 上 cmd+ctrl+shift+4 截图到剪贴板再 ctrl+v 粘贴）、用 tab 补全引用文件、贴 URL 并可用 /allowed-tools 把常用域名加入白名单。

观点 5：尽早、频繁地纠偏

四个纠偏工具：① 让 Claude 先出计划、确认前不许写码；② 按 Esc 随时打断（保留上下文，可重新引导）；③ 双击 Esc 跳回历史、编辑之前的 prompt 换方向重来；④ 让 Claude 撤销（undo）修改。同时用 /clear 在无关任务之间重置上下文，避免无关对话、文件内容稀释性能。

六大实践板块详解

1. 定制环境（Customize your setup）

  • CLAUDE.md：每次会话开始时自动载入的特殊文件，适合记录常用 bash 命令、核心文件、代码风格、测试说明、仓库礼仪（分支命名、merge vs rebase）、开发环境怪癖等。可放在仓库根目录（推荐入 git 与团队共享）、任意父目录（monorepo 场景）、子目录（按需载入）、或 ~/.claude/CLAUDE.md（全局）。运行 /init 可自动生成初版。
  • 调优 CLAUDE.md：它本质是 prompt，要像调 prompt 一样迭代；按 # 键可随时让 Claude 把指令并入相应 CLAUDE.md；Anthropic 内部会用 prompt improver 处理它，并加 "IMPORTANT"/"YOU MUST" 强调关键规则。
  • 工具白名单：默认对所有可能修改系统的操作请求授权（保守安全设计）。四种管理方式：提示时选 "Always allow"、/allowed-tools 命令（如 Bash(git commit:*)）、手改 .claude/settings.json、CLI 参数 --allowedTools。
  • gh CLI：用 GitHub 就装 gh，Claude 天然会用它建 issue、开 PR、读评论。

2. 给 Claude 更多工具（MCP 与自定义命令）

  • Claude Code 继承你的 bash 环境；自定义工具要告知用法（给例子、让它跑 --help、写进 CLAUDE.md）。
  • Claude Code 同时是 MCP 客户端与服务端；作为客户端可在项目配置、全局配置或入库的 .mcp.json 三处接入 MCP server（如 Puppeteer、Sentry），排障可加 --mcp-debug。
  • 自定义斜杠命令：把重复工作流的 prompt 模板放进 .claude/commands/*.md，支持 $ARGUMENTS 传参。文中例子：fix-github-issue 命令自动完成「gh 查看 issue → 理解问题 → 搜代码 → 修复 → 写测试 → lint/typecheck → 提交 → 开 PR」八步。

3. 常见工作流（Common workflows）

工作流要点
Explore, plan, code, commit四步走；用 think→ultrathink 分级触发扩展思考；计划可固化为文档/issue 以便回退
TDD：写测试→提交→写码→迭代→提交明确告知在做 TDD 以防 mock 实现；先确认测试失败；实现阶段不许改测试；可用独立 subagent 检查是否过拟合测试
视觉迭代给 Claude 截图能力（Puppeteer MCP / iOS 模拟器 MCP / 手动粘贴），给视觉稿，实现→截图→对比→迭代至匹配
Safe YOLO 模式--dangerously-skip-permissions 跳过全部授权（适合修 lint、生成样板代码）；务必在无网络容器中使用以防数据丢失/外泄（prompt injection）
Codebase 问答像问同事一样问代码库；Anthropic 内部的核心 onboarding 流程，显著缩短上手时间
git / GitHub / JupyterAnthropic 工程师 90%+ 的 git 交互交给 Claude（搜历史、写 commit message、解 rebase 冲突）；GitHub 侧可开 PR、一次性修复 review 评论、修构建、分类 issue；Jupyter notebook 可读写并解释图表输出

4. 优化交互（Optimize your workflow）

  • 指令具体化（见观点 4）；给图片；用 tab 补全提及文件；给 URL。
  • 尽早纠偏 + /clear 保持上下文聚焦。
  • checklist / scratchpad：大规模任务（代码迁移、批量修 lint）让 Claude 把错误清单写进 Markdown 文件（或 GitHub issue），逐条修复、验证、勾掉——把任务状态外化到文件，突破上下文限制。
  • 数据传入四法：直接粘贴、管道（cat foo.txt | claude，适合日志/CSV）、让 Claude 自己拉取（bash/MCP/斜杠命令）、让它读文件或 URL。

5. Headless 模式自动化

claude -p "<prompt>" 以非交互方式运行，适合 CI、pre-commit hook、构建脚本；--output-format stream-json 输出流式 JSON。注意 headless 模式不跨会话持久化。两个官方用例：issue 分诊（Claude Code 公开仓库就用它给新 issue 自动打标签）与当作 linter（做传统工具查不出的主观审查：错别字、过期注释、误导性命名）。

6. 多 Claude 工作流（Multi-Claude workflows）

  • 写码/验证分离：一个 Claude 写代码，/clear 或另开终端让第二个 Claude 审查，再让第三个（干净上下文）综合代码与评审意见修改——分离上下文常好于单实例包办。也可一个写测试、另一个写代码通过测试。
  • 多 checkout / git worktrees：建 3–4 个 git checkout 各开一个终端跑不同任务；或用更轻量的 git worktree add ../project-feature-a feature-a 让多个 Claude 并行做互不重叠的任务（一个重构认证系统、另一个做数据可视化组件），互不等待、无合并冲突。建议统一命名、每个 worktree 一个终端标签页、用完 git worktree remove 清理。
  • headless + 自定义 harness：两种模式——Fan-out（扇出）：让 Claude 先生成任务清单（如 2000 个待迁移文件），再循环调用 claude -p "migrate foo.py from React to Vue. … return OK or FAIL" --allowedTools Edit Bash(git commit:*)；Pipelining（流水线）：claude -p "<prompt>" --json | your_command 把 Claude 嵌进数据处理管道。

结论与建议

本文没有实验数据，其结论是经验性的模式汇总。核心建议可归纳为：

  1. 把 CLAUDE.md 当作频繁使用的 prompt 来迭代调优，并入库共享让团队复利。
  2. 默认走 Explore → Plan → Code → Commit，需要深思时用 think/ultrathink 分级。
  3. 永远给 Claude 可验证的迭代目标（测试、视觉稿），2–3 轮迭代后产出显著更好。
  4. 把上下文当作核心资源：/clear、subagent、checklist 文件三管齐下。
  5. 规模化时组合 headless 扇出 + git worktrees 并行，把 Claude Code 变成可编程的智能体基础设施。

  • 与 CS329Z 第 15 讲（Coding & Software Agents）的关系：该讲剖析编码智能体如何端到端工作（SWE-agent、Claude Code、OpenHands 架构），本文正是 Claude Code 这一代表性产品的官方实践指南，展示了「scaffold（脚手架）即设计决策」的具体形态——CLAUDE.md（持久上下文）、hooks/权限（安全边界）、worktrees（并行隔离）、headless（可编程性）都是 scaffold 的组成部分。
